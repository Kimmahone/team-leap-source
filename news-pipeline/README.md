# 빅카인즈 뉴스 자료 인계·재생성 안내

이 폴더는 기사 원본을 보관하는 곳이 아니라, **같은 조건으로 서비스용 자료를 다시 만드는 곳**입니다.

## 1. 무엇을 어디에 두나

| 구분 | 보관 위치 | GitHub | 대시보드 배포 |
|---|---|---:|---:|
| 빅카인즈 원본 `NewsResult_*.xlsx` | 접근 제한된 팀 드라이브 | 금지 | 금지 |
| 검색식·수집 기간·변환 코드·스키마 | 이 폴더의 `BIGKINDS_DOWNLOAD.md`와 코드 | 포함 | 제외 |
| `source-manifest.json`(파일명·행 수·SHA-256) | 이 폴더 + 원본 공유 폴더 | 포함 | 제외 |
| 연도별 기사 메타데이터 전체 | `news-pipeline/work/archive/` + 제한된 팀 드라이브 | 금지 | 금지 |
| 최근 집계·키워드·소수 근거 기사 | `prototype/assets/news/` | 포함 | 포함 |
| 기사 본문·본문 발췌 | 원본 내부에서만 열람 | 금지 | 금지 |

빅카인즈 다운로드 파일은 내부 인계용입니다. 다음 담당자에게는 원본 공유 폴더 접근권한을 부여하되, 외부 링크 공개나 GitHub 업로드는 하지 않습니다.

## 2. 팀 드라이브 권장 구조

```text
TEAM LEAP/학령인구/뉴스원본/
  00_읽어보기.md
  01_BIGKinds_원본/
    NewsResult_20160101-20161231.xlsx
    ...
  02_인계검증/
    source-manifest.json
  03_검색조건/
    BIGKINDS_DOWNLOAD.md
```

권한은 `TEAM LEAP 담당자만 보기/다운로드`로 설정합니다. 담당자가 바뀌면 개인 계정 소유 파일을 넘기는 대신 팀 공유 폴더의 구성원만 교체합니다.

## 3. 다시 만드는 명령

```bash
cd news-pipeline
npm install
npm run build -- --raw "/팀드라이브에서 내려받은 원본 폴더"
npm run check
```

공개 집계 결과는 `06. 실행계획(1)/prototype/assets/news/`, 내부 연도별 목록은 `news-pipeline/work/archive/`에 생깁니다. `work/`는 GitHub와 배포에서 제외됩니다. `source-manifest.json`의 SHA-256이 인계받은 원본과 맞는지도 함께 확인합니다.

## 4. 공개 산출물 규칙

- 집계값과 화면에 인용하는 소수 근거 기사의 제목, 언론사, 발행일, 원문 링크, 주제, 시군, 추출 키워드만 공개합니다.
- 전체 연도별 기사 목록은 공개하지 않습니다.
- 기사 본문, 본문 앞부분, 인물 목록은 공개 파일에 넣지 않습니다.
- 전체 경북 교육 뉴스는 분석용 분모일 뿐, 기본 화면에는 6대 학령인구 주제 기사만 사용합니다.
- 네이버 API 최신 뉴스와 빅카인즈 과거 자료는 서로 다른 출처로 보존합니다.
- 기사량은 사회적 관심의 신호이지 학생 수·학교 수 변화의 직접 증거가 아닙니다.

## 5. 매일 뉴스와 3일 주기 분석·이슈페이퍼

- 네이버 뉴스는 매일 오전 7시 37분(한국시간)에 수집합니다.
- 이슈 분석과 이슈페이퍼는 같은 자동 작업 안에서 **마지막 생성일로부터 3일이 지난 날** 함께 생성합니다.
- 달력의 `1·4·7일`처럼 날짜를 고정하지 않고 마지막 성공일을 확인하므로 월말에도 실제 3일 간격을 유지합니다.
- 예약 작업을 하루 놓치면 다음 일일 실행에서 바로 보충 생성합니다.
- 수동 실행(`workflow_dispatch`) 때는 현재 자료로 같은 기준일의 분석과 페이퍼를 강제로 갱신합니다.
- 같은 기준일은 같은 ID를 사용하므로 다시 실행해도 중복되지 않습니다.
- `prototype/assets/news/snapshots/index.json`에 이슈 분석 이력을 최신순으로 최대 40회 보관합니다.
- `prototype/assets/news/issues/index.json`에 최신순으로 최대 52호를 보관합니다.
- 화면의 `지난 이슈 분석`과 `지난 이슈페이퍼`에서 날짜별 자료를 선택할 수 있고, 페이퍼는 `인쇄 · PDF 저장`으로 출력합니다.
- 자동 분석은 네이버 검색 API의 최근 30일을 직전 30일과 비교합니다. 자동 이슈페이퍼는 최근 7일을 요약하되 **3일마다 새 호를 발행**합니다.
- BIG Kinds 원본을 수동 재분석한 정밀 분석호도 같은 이력에 보존하되 화면에서 출처를 구분합니다.

로컬에서 현재 자료로 분석과 이슈페이퍼를 강제 생성하려면 다음을 실행합니다.

```bash
npm --prefix news-pipeline run insights -- --force
```

자동 작업과 같은 방식으로 3일이 지났을 때만 생성하려면 `--force`를 빼고 실행합니다.

## 6. 다음 담당자가 확인할 것

1. 팀 드라이브의 원본 파일 수와 `source-manifest.json` 파일 수가 같은가
2. 파일별 SHA-256이 같은가
3. `npm run build` 결과의 원본 행 수·중복 제거 수·6대 주제 수가 이전 기록과 맞는가
4. `npm run check`가 모두 통과하는가
5. 대시보드에서 최신 뉴스와 빅카인즈 분석의 출처·기준일이 구분되는가

원본 파일을 메신저로 한 번 보내고 끝내지 않습니다. **팀 공유 폴더 접근권한 + GitHub 재생성 코드 + 체크섬** 세 가지가 모두 있어야 인계가 완료됩니다.

새 자료를 내려받는 화면별 순서는 [`BIGKINDS_DOWNLOAD.md`](BIGKINDS_DOWNLOAD.md)를 따릅니다.
시각화·벡터화·유사도 분류와 EDSS 결합 원칙은 [`ANALYSIS_METHOD.md`](ANALYSIS_METHOD.md)를 따릅니다.
