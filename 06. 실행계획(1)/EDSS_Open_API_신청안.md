기준일: 2026-08-31

>
> 인증키는 API별로 나뉘어 `Kimmahone/team-leap-source`의 GitHub Actions Repository Secret에 있습니다. Cloudflare에는 넣지 않습니다 — 브라우저·Pages Function이 EDSS를 호출하지 않습니다.

## 요청주소 채우기 — 지금 남은 단 하나

수집기(`open api/bake-edss.mjs`)는 **요청주소를 코드에 박지 않습니다.** `open api/edss-endpoints.json`의 `url` 칸에서 읽습니다. 지금 그 칸은 비어 있고, 비어 있으면 수집기는 조용히 넘어가지 않고 「주소가 없다」고 말한 뒤 멈춥니다.

1. 신청한 곳에 로그인 — [data.go.kr](https://www.data.go.kr) **마이페이지 → 데이터활용 → Open API → 활용신청 현황**, 또는 [edss.moe.go.kr](https://edss.moe.go.kr) **신청내역**
2. 승인된 API 이름을 눌러 **참고문서**·**상세기능**·**개발명세서**의 **요청주소(엔드포인트)** 를 복사
3. `open api/edss-endpoints.json`의 그 API `url` 칸에 붙여넣기 — `?serviceKey=…` 앞까지만
4. 커밋 → GitHub Actions에서 **공공데이터 정기 확인 및 갱신**을 `edss-probe`로 실행

한 개만 먼저 시험해 보려면 파일을 고치지 않고도 됩니다. 워크플로 실행 화면에서 `edss_only`에 API 이름(예: `studentStatus`), `edss_url`에 주소를 넣으면 그 한 번만 그 주소를 씁니다.

`edss-probe`는 API마다 **한 번씩만** 호출해 응답의 칸 이름과 총건수를 `open api/data/edss-probe.json`에 적습니다. 그 파일에는 **인증키도 학교 이름도 값도 들어가지 않습니다** — 칸 이름과 자료형만 담습니다.

## 승인 직후 반드시 받을 것

1. API 개발 문서의 요청 URL, 요청변수, 응답 예시(JSON)와 호출 제한
2. 코드북: 학교/기관코드, 시도·시군구 코드, 학교급·학년·설립유형·운영상태 코드
3. 학교별·학년별 자료인지, 시도·시군 합계만 제공하는 자료인지 확인
4. 조사연도와 공시·집계 기준일, 통폐합·교명 변경 학교의 식별 규칙
5. 위치정보의 좌표계와 경도·위도 제공 여부

응답 예시는 인증키·개인정보를 지운 뒤 전달하면 된다.

**수집·검사·자동 갱신 코드는 이미 연결되어 있다**(2026-08-31). 응답의 칸 이름을 미리 모르는 채로 붙였기 때문에, 수집기는 칸 이름을 **보고 짐작합니다**. 짐작한 결과는 `edss-probe.json`의 `고른칸`·`고른까닭`에 적히므로 확인할 수 있고, 틀렸으면 `edss-endpoints.json`의 `fields`에 실제 이름을 적어 고정합니다.

짐작이 특히 조심하는 것은 **학생수·학급수** 칸이다. `특수학급학생수`·`남학생수`·`교원수` 같은 곁가지를 전체 학생수로 집으면 경북 학생이 조용히 1/20이 되는데 화면은 멀쩡해 보인다. 그래서 그런 낱말이 든 칸은 아예 후보에서 뺀다(`tests/edss.test.mjs`가 이 규칙을 못 박고 있다).

## 지금은 신청하지 않아도 되는 API

- 교복구매현황(EDSS): 학령인구·학교배치 분석과 직접 관련이 없음
- 교육운영특색사업계획(EDSS): 정책사업 원문이 필요할 때 다시 검토. 현재 핵심 시계열에는 불필요
- 유치원 공시 대체용: EDSS를 유치원알리미 대체제로 가정하지 않고 유치원알리미 API와 교육청 운영상태 명부를 사용

## 신청 범위

- 지역: 경상북도
- 기간: 2016~2026(가능한 최초 연도부터 최신 조사연도까지)
- 단위: 학교단위·학년단위 연간 집계
- 개인자료: 불필요
- 필수 연결키: 조사연도+학교/기관코드
- 출력형식: JSON. 코드북·필드 정의서도 함께 확보

## 복사용 신청 목적

> 경상북도 초·중·고 학교의 2016~2026 학교별·학년별 학생수·학급수와 학교속성·학교개황을 조사연도와 기관코드로 연결하여 학령인구 감소 추이와 학교규모 변화를 분석하고, 대시보드의 임시 예측모형을 검증하고자 합니다. 개인단위 자료는 필요하지 않으며 학교단위·학년단위 집계자료만 요청합니다.

## 도움말에서 거부해야 할 경우

아래 중 하나라도 학교단위 연결이 불가능하면 해당 API는 현재 목적에 부족합니다.

- 학교/기관코드가 없고 시도 합계만 제공
- 조사연도가 없어 여러 해 자료를 연결할 수 없음
- 학년 코드가 없어 출생 코호트 검증이 불가능
- 통폐합·교명변경 코드 이력이 없는데 단일 학교 시계열로 간주해야 함
