## 0. 왜 고치나 — 한 문장

두 탭은 **틀린 수를 보여 주지 않습니다.** 검증도 되어 있습니다.
문제는 **화면이 결정을 도와주는 모양이 아니라는 것**입니다.

- 현황 탭은 **경북 전체만** 보여 줍니다. 정책은 시군 단위로 집행되는데
  도 합계로는 어디부터 할지 정할 수 없습니다.
- 시뮬레이터는 **엔진이 좋은데** 그 좋은 점이 라디오 단추 여섯 개에 숨어
  있습니다. 결과도 표 두 개뿐이라 무엇이 달라지는지 눈에 들어오지 않습니다.

고쳐 쓸 때 **두 사람이 함께 지킬 세 가지**는 2장에 있습니다.

## 1. 겹치지 않게 일하는 법

### 1-1. 고치는 파일은 하나뿐입니다

```
06. 실행계획(1)/prototype/index.html     ← 화면·스타일·코드가 모두 여기
06. 실행계획(1)/prototype/test.js        ← 검사
```

번들러도 `package.json` 도 없습니다. `index.html` 한 장에 CSS·JS·자료가
모두 들어 있습니다. **10,000줄이 넘습니다.** 그래서 구간을 나눕니다.

### 1-2. 각자의 구간 (2026-09-10 기준 줄 번호)

| 구간 | 줄 | 누구 |
|---|---|---|
| `<section id="view-status">` 마크업 | 약 1982 ~ 2086 | **현황** |
| `<section id="view-sim">` 마크업 | 약 2163 ~ 2304 | **시뮬** |
| `function renderStatus()` | 약 6796 | **현황** |
| `function renderTrendLineChart()` | 약 6841 | **현황** |
| `function renderPaxPyramid()` | 약 7612 | **현황** |
| `let dsKind` · `yr-past` · `yr-future` 배선 | 약 6790 | **현황** |
| `function renderSim()` | 약 7057 | **시뮬** |
| `predYear` 및 기준 라디오 배선 | 약 6947 | **시뮬** |
| `function simForward()` | 약 7050 | **시뮬** |

**새 CSS 는 각자 제 자리에 모아 씁니다.** 파일 가운데 아무 데나 끼워 넣지
말고, 아래 표시 주석을 만들어 그 안에만 씁니다.

```css
/* ══ 학령인구 현황 ═════════════════════════ */   ← 현황이 쓰는 자리
/* ══ 학생수 시뮬레이터 ═════════════════════ */   ← 시뮬이 쓰는 자리
```

### 1-3. 손대면 안 되는 자리

아래는 **다른 화면이 함께 쓰는 것**입니다. 고쳐야 할 일이 생기면
**고치기 전에 상대에게 알리고**, 고친 뒤에는 커밋 메시지 첫 줄에
`[공용]` 을 답니다.

|---|---|---|
| `series(kind, year)` | 4152 | 현황 · 내보내기 |
| `forwardStudents` / `forwardShare` | 5466 · 5475 | 현황 · 시뮬 · 지도 |
| `regionStudents` / `regionTotalStudents` | 5492 · 5516 | 현황 · 지도 |
| `schoolStudentsAt` | 5541 | 지도 · 학교 카드 |
| `schoolCardHtml` / `schoolSparkSvg` | 5811 · 5725 | 지도 · (앞으로) 시뮬 |
| `showView` | 4374 | 전부 |

| `BASE` · `SIGUNGU` · `KOSIS_POP` · `EDSS_FWD_RAW` | 4064 · 3160 · 4100 · 4114 | 전부 |
| `mv*` 로 시작하는 모든 것 | 9000 이후 | 지도 전용 — **건드리지 않습니다** |
| `parked-home` `<template>` 안 | 1605 이후 | 치워 둔 화면 — 그대로 둡니다 |

### 1-4. `test.js` 는 **맨 뒤에만** 붙입니다

검사 파일도 하나입니다. 가운데를 고치면 서로 부딪힙니다.
**각자 파일 맨 끝(`console.log(통과/실패)` 바로 위)에** 자기 구간을 답니다.

```js
console.log('\n■ 〔현황〕 시군을 고를 수 있다');     // ← 현황은 이 표시로 시작
console.log('\n■ 〔시뮬〕 시나리오를 이름으로 고른다'); // ← 시뮬은 이 표시로 시작
```

기존 검사를 **지우지 마세요.** 깨지면 그 검사가 지키던 것이 무엇인지 먼저
읽고, 정말 바뀌어야 하는 것이면 검사 문구도 함께 고칩니다.

### 1-5. 합칠 때

각자 `origin/main` 에서 브랜치를 따고, 끝나면 PR 을 냅니다.
**먼저 끝난 쪽이 먼저 머지합니다.** 나중 쪽은 `origin/main` 을 받아
`git rebase origin/main` 한 뒤 검사를 다시 돌리고 PR 을 냅니다.

충돌이 나면 대개 `index.html` 한 곳입니다. 구간이 다르므로 **양쪽을 모두
남기는 것**이 정답인 경우가 거의 전부입니다.

## 2. 두 사람이 함께 지킬 세 가지

**하나 — 화면은 차트 목록이 아니라 «질문»으로 시작합니다.**
「지금 무엇을 정하려 하십니까」가 먼저 오고 그림은 그 뒤에 옵니다.

**둘 — 학생 수 옆에는 늘 «학급 수와 교원 수»를 붙입니다.**
「학생 98,072명 감소」는 결정을 만들지 못합니다. 「학급 4,640개 · 교원
7,600여 명」이 되어야 예산과 정원의 말이 됩니다.

**셋 — 없는 것은 없다고 적습니다.**
자료가 없는 해를 앵커로 이어 그리면 그 선이 실적처럼 보입니다.
실적과 전망은 **선의 모양으로도** 갈라야 합니다(실선 · 점선). 색만으로
가르면 색을 못 보는 사람에게는 한 선입니다.

## 3. 학령인구 현황 — Claude Code

### 3-1. 지금 무엇이 문제인가

1. **경북 전체만 나옵니다.** 시군 선택이 없습니다.
2. 막대(과거·현재·미래) · 피라미드 · 선그래프 · 표가 세로로 **나열**돼 있고
   서로 대화하지 않습니다. 무엇을 보라는 말이 없습니다.
3. 「학령인구」와 「학생수」를 단추로 갈아 끼우는데 **두 수가 왜 다른지는
   말하지 않습니다.** 2026년 고등학교는 학령인구 88천 명, 재학생 63천 명입니다.
4. 차트 제목에 **「Pure SVG 오프라인 차트」** 가 적혀 있습니다. 읽는 사람에게
   뜻이 없는 말입니다.

### 3-2. 할 것

#### ① 코호트 진행표 — 이미 학교에 앉아 있는 아이로 6년 뒤를 말한다

가장 센 자료인데 화면에 없습니다. 학년별 인원은 **917개 학교 전부** 갖고
있습니다(`sc.grades`, `sc.gcls`).

| 2026년 지금 | 인원 | 도착하는 해 | 그때 무엇이 되나 |
|---|---:|---|---|
| 초등 6학년 | 19,266 | 2027 | 중학교 1학년 |
| 초등 1학년 | **12,765** | 2032 | 중학교 1학년 — 지금보다 **34% 적게** |
| 중학교 1학년 | 19,554 | 2029 | 고등학교 1학년 |
| 고등학교 1학년 | 21,863 | 2028 | 졸업 |

여기에는 출산율 가정도, 추계 모형도 들어가지 않습니다. **이미 태어나 학교에
다니는 아이를 세는 것뿐**입니다. 「예측일 뿐」이라는 반박을 받지 않습니다.

**고등학교는 아직 감소가 도착하지 않았습니다.** 고1이 중1보다 많습니다.
초등에서 시작된 감소가 중학교에 6년, 고등학교에 9년 걸려 도착합니다.
이 시차를 적으면 「지금은 괜찮은데 왜 서두르나」에 답할 수 있습니다.

#### ② 22개 시군을 한 화면에 나란히

시군마다 작은 카드 하나 — 10년 추이 선과 2026→2036 감소율.
정렬은 감소율 순 · 학생 수 순 · 이름 순.

```
울릉 9.5%  봉화 7.8%  고령 7.7%  청도 7.5%  영덕 6.1%  성주 6.0%
```

이 수는 `BASE[lv][시군].rate` 로 **이미 계산되어 있습니다.** 다만 화면
어디에도 나오지 않습니다. 나란히 놓지 않으면 「어디가 먼저인가」가 나오지
않습니다.

카드를 누르면 그 시군으로 화면 전체가 바뀝니다.

#### ③ 두 수가 다른 까닭을 화면이 말한다

2026년 고등학교 — 주민등록 기준 **88천 명**, 학교알리미 재학생 **63천 명**.
25천 명이 벌어집니다. 초·중은 거의 같습니다.

까닭을 확인했습니다. `open api/bake-kosis.mjs` 66~68줄입니다.

```js
if(age>=6 && age<=11) result[year].초+=value;      // 6살 — 초등 6학년
else if(age>=12 && age<=14) result[year].중+=value; // 3살 — 중학 3학년
else if(age>=15 && age<=18) result[year].고+=value; // ★ 4살인데 고등학교는 3학년
```

**고 구간이 15~18세 네 살인데 고등학교는 세 학년입니다.** 한 살이 더
들어갑니다. 유출이 아닙니다. 88 ÷ 4 × 3 ≈ 66천 — 재학생 63천과 가깝습니다.

→ 화면에 이 설명을 적고, **구간을 맞춘 뒤에 남는 차이**를 따로 보여 줍니다.
그 차이가 큰 시군이 아이가 밖에서 학교를 다니는 시군입니다.

#### ④ 학생 수를 학급 수와 교원 수로 옮겨 적는다

| 2026 | 값 |
|---|---:|
| 학생 (초·중·고) | 227,484 |
| 학급 | 11,940 |
| 교원 | 19,353 |

2036년에 학생이 129,412명이 되면, **학급당 인원을 지키면 학급이 줄고,
학급 수를 지키면 학급당 인원이 줄어듭니다. 어느 쪽을 고를지가 정책입니다.**
두 갈래를 함께 보여 주고 고르게 합니다.

#### ⑤ 언제 무슨 일이 오는지 달력으로

- **2029** — 초등학생이 2026년의 80% 아래로
- **2032** — 지금 초1이 중학교에 들어갑니다. 중학교 감소가 여기서 가팔라집니다
- **2035** — 고등학교에 그 물결이 도착합니다

#### ⑥ 구현 용어 걷어내기

「Pure SVG 오프라인 차트」 · 「Line Chart」 같은 말을 지웁니다.
읽는 사람은 무엇으로 그렸는지 궁금하지 않습니다.

### 3-3. 받아들일 조건

- 시군을 고르면 **그 시군의 코호트·추이·표가 모두** 따라옵니다
- 실적과 전망이 **선의 모양으로도** 갈립니다
- 화면에 뜬 모든 수는 눌러서 **어디서 왔는지** 되짚을 수 있습니다
- 검사가 「도 합계와 시군 합계가 맞는다」를 봅니다

## 4. 학생수 시뮬레이터 — Codex

### 4-1. 이 탭이 지금 무엇을 하나 (읽고 시작하세요)

**엔진은 좋습니다. 지우지 마세요.** 핵심은 이것입니다.

> **무엇을 고정할지 고르면 나머지가 결과로 나옵니다.**
>
> - **학교 수 기준** — 학교·학급 수를 정하면 → **학급당 평균 학생수**가 결과
> - **학급당 학생 수 기준** — 학급당 인원을 정하면 → **필요한 학급·학교 수**가 결과

화면에 파랑은 **입력한 기준**, 빨강은 **산출 결과**입니다. 이 규칙을
그대로 지켜 주세요.

기준자료(2026)는 **실적**입니다 — 학교알리미 공시 917교의 시군별 합계.
모의전망(2027~)은 **공식 예측이 아닙니다** — 시군·학교급별 감소율을 가정해
곱한 값이고, 그 감소율은 **이 화면이 정한 가정**입니다.

### 4-2. 할 것

#### ① 라디오 여섯 개를 «이름 붙인 시나리오» 로

지금은 「학교 수 기준 / 학급당 학생 수 기준」과 그 아래 세부 여섯 갈래를
조합해야 합니다. 사람이 실제로 묻는 말로 앞면을 만들고, 세부 설정은
**「자세히 고치기」로 접어 둡니다.**

| 카드 | 무엇을 고정하나 | 무엇이 결과로 나오나 |
|---|---|---|
| **지금 그대로 두면** | 학교 수 · 학급 수 | 학급당 몇 명이 되나 |
| **학급당 20명을 지키면** | 학급당 인원 | 학급 · 학교가 몇 개 필요한가 |
| **복식학급 없이 가면** | 학년당 1학급 이상 | 학급 · 학교가 몇 개 필요한가 |
| **통학 30분 안에서** | 지리 제약 | 어디까지 되나 |

앞의 셋은 **지금 엔진 그대로** 됩니다(각각 `sch-basis=fixed`,
`cls-basis=pm`, `cls-basis=grade` 에 해당). 네 번째는 새로 만들어야 하고,
지도가 쓰는 좌표(`sc.lat`/`sc.lon`)와 `haversineKm`(7718줄)을 씁니다.
**네 번째는 마지막에 하세요.** 앞의 셋만 해도 이 탭의 성격이 바뀝니다.

#### ② 표 앞에 «무엇이 달라지는가» 를 놓는다

지금은 기준표와 모의표가 나란히 있고 사람이 눈으로 빼야 합니다.

- 맨 위에 **차이만** 큰 글씨로 셋 — 학생 △ · 학급 △ · 학교 △
- 그 아래 시군별로 **줄어드는 양만** 막대로
- 표는 그대로 두되 **아래로** 내립니다

> **표를 없애지 마세요.** 표는 옮겨 적고 검산하는 자리입니다. 보고서에
> 붙이려면 표가 있어야 합니다. 다만 **첫눈에 들어오는 자리를 표에 주지
> 않습니다.**

#### ③ 시군에서 «학교» 까지 내려간다

교직원이 이 화면에서 알고 싶은 것은 하나입니다. **우리 학교가 여기 있는가.**

학교별 전망은 이미 계산됩니다 — `schoolStudentsAt(sc, year)` (5541줄).
조건에 걸리는 학교를 이름으로 보여 줍니다.

> ### ⚠ 여기는 반드시 지켜 주세요
>
> 학교 이름에 **「통폐합 대상」이라는 딱지를 붙이면** 이 대시보드는 그날로
> 못 쓰는 물건이 됩니다.
>
> - 이름은 **「함께 살펴볼 학교」** 입니다
> - 목록 옆에 **늘** 이 문장이 따라갑니다 —
>   **「이 목록은 검토 순서를 정하지 않습니다. 학교별 판단은 그해
>   경상북도교육청 적정규모학교 육성 계획을 따릅니다.」**
> - 순위를 매기지 않습니다. 번호를 붙이지 않습니다.

학교 이름을 누르면 **지도 탭**으로 넘어가게 하려면
`selectSchool(sc)` 를 부르고 `location.hash = 'map'` 으로 옮기면 됩니다.
(`selectSchool` 은 **5913줄**, 지도가 알아서 왼쪽 칸을 펼칩니다.)

#### ④ 목표에서 거꾸로 묻는다

정책은 대개 **목표에서 출발**합니다. 엔진을 역으로 돌립니다.

- 학급당 20명을 지키려면 **몇 년까지** 지금 학교 수로 버틸 수 있나
- 봉화의 초등학교를 지금 **14곳**으로 유지하면 학급당 몇 명이 되나
- 복식학급을 만들지 않으려면 **언제** 무엇을 결정해야 하나

#### ⑤ 이 셈법이 얼마나 맞았는지 밝힌다

이 탭의 가장 큰 약점은 **가정**입니다. 그런데 **10년 실적이 이미 심겨
있습니다** — `EDSS_SCHOOL_YEARS` = 2016~2025, 898개 학교.

경북 초등학생 2016년 **126,286명** → 2026년 **100,501명**, **20.4% 감소**.
같은 셈법을 2016년에 돌렸다면 2026년을 얼마나 맞혔는지 그 자리에 적습니다.

> 틀렸으면 **얼마나 틀렸는지 적습니다.** 그것이 이 화면을 믿을 수 있게
> 만드는 유일한 길입니다. 맞았다고 우기는 것보다 훨씬 셉니다.

### 4-3. 받아들일 조건

- 처음 온 사람이 **카드 이름만 읽고** 무엇을 하는 화면인지 안다
- 「몇 명이 될 것이다」로 읽히지 않는다. **기준을 바꿔 가며 어느 쪽으로
  얼마나 움직이는지** 보는 자리라는 것이 화면에 적혀 있다
- 학교 목록에 위의 ⚠ 문장이 **늘** 붙는다
- 검사가 「시뮬레이터와 현황 탭이 같은 해에 같은 수를 말한다」를 계속 지킨다
  (이미 있는 검사입니다 — 깨뜨리지 마세요)

## 5. 이 코드에서 실제로 걸려 넘어진 것들

지도를 고치며 부딪힌 것입니다. **같은 데서 또 넘어지지 않도록** 적어 둡니다.

### 5-1. `return` 뒤에 줄을 바꾸면 아무것도 돌아오지 않습니다

```js
return
  '<div>' + …        // ← 자바스크립트가 return 에서 문장을 끝냅니다
```

카드가 통째로 빈 값이 되었습니다. 오류도 나지 않습니다.
**첫 조각은 반드시 `return` 과 같은 줄에** 둡니다.

### 5-2. CSS 변수를 «글자로» 읽으면 색이 아닙니다

이 앱의 토큰은 `--brand: var(--leap-blue)` 처럼 **별칭**입니다.
`getComputedStyle(...).getPropertyValue('--brand')` 는
`"var(--leap-blue)"` 라는 **글자**를 돌려줍니다.

SVG 의 `fill`/`stroke` 에 `var(--…)` 를 그대로 쓰는 것은 **됩니다.**
자바스크립트가 색 값을 필요로 할 때만 문제입니다.

### 5-3. 문서에 없는 것에 리스너를 달면 앱 전체가 멎습니다

```js
document.getElementById('없는-것').addEventListener(…)   // ← 여기서 스크립트가 끝납니다
```

그 뒤 줄이 **하나도** 실행되지 않습니다. 화면에는 「빈 화면」으로만 보입니다.
`onEl(id, ev, fn)` 도우미가 있습니다(**4322줄**). **그것을 쓰세요.**

### 5-4. HTML 주석 안에 붙임표 두 개를 넣지 마세요

`var(--line)` 이 든 구간을 `<!-- -->` 로 감싸면 **거기서 주석이 끊깁니다.**
나머지가 화면에 쏟아집니다. 큰 덩어리를 치울 때는 `<template>` 을 씁니다.
(검사가 이것을 봅니다.)

### 5-5. 스타일이 없으면 화면이 «비지» 않고 «못생겨집니다»

CSS 규칙을 실수로 지우면 오류로 보이지 않고 **디자인이 나쁜 것으로**
보입니다. 찾기 어려운 종류입니다. CSS 를 지울 때는 지우는 범위를 눈으로
한 번 더 확인하세요.

### 5-6. 검사의 DOM 은 «가짜» 입니다

`test.js` 는 최소 DOM 스텁 위에서 스크립트를 **실제로 실행**합니다.
`getElementById` 는 **없는 것도 만들어서 돌려줍니다.** 그래서 검사는
통과하는데 브라우저에서는 멎는 일이 생깁니다.
**브라우저로 한 번은 열어 보세요.**
