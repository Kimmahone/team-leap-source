# 2. 찾은 결함 5건 — **모두 고쳤습니다**

> 아래는 «무엇이 잘못돼 있었는지»의 기록입니다. 같은 일이 되풀이되지 않게 남깁니다.

## ★ 결함 1 — 없는 학생 791명이 화면에 표시됩니다 〔가장 중요〕

### 무슨 일인가

**특수학교가 한 곳도 없는 15개 시군에, 특수학교 학생 791명과 학급 158개가 존재하는 것으로 계산됩니다.**

| 시군 | 특수학교 | 화면상 학생 수 |
|---|---|---|
| 김천 | **0곳** | **160명** |
| 영주 | **0곳** | **115명** |
| 문경 | **0곳** | **66명** |
| 울진 | 0곳 | 40명 |
| 의성·예천 | 0곳 | 각 35명 |
| 영덕 | 0곳 | 25명 |
| 봉화·영양·청송 외 6곳 | 0곳 | 각 20명 안팎 |
| **합계 15개 시군** | **0곳** | **791명 · 158학급** |

### 화면에 어떻게 드러나는가

| 위치 | 표시값 | 실제값 | 오차 |
|---|---|---|---|
| **학교급 「특수」 선택 시 · 학교당 평균 학생 수** | **300.6명** | **201.8명** | **+49%** |
| 학교급 「전체」 · 전체 학생 수 | 254,451명 | 253,660명 | +791명 |
| 학교급 「전체」 · 학급당 평균 | 18.1명 | 18.3명 | 어긋남 |
| **간편 지도에서 학교급 「특수」 + 학생 수 선택** | **15개 시군에 동그라미가 찍힘** | 찍히면 안 됨 | — |

특히 **「학교당 평균 300.6명」은 어디에도 존재하지 않는 수**입니다.
분자에는 유령 791명이 들어가 있고, 분모(8곳)에는 안 들어가 있어서 생긴 값입니다.

### 왜 이런 일이

기준자료(`BASE`)를 만들 때 조건이 이렇게 되어 있습니다.

```
if (학교수 > 0 && 실적학교수 === 학교수) → 실적을 그대로 씁니다  ✅
else                                    → 옛날 더미값으로 채웁니다  ← 여기
```

특수학교가 **0곳**인 시군은 `학교수 > 0`이 거짓이라 **else로 떨어집니다.**
그리고 else는 「중학교 학생 수 × 0.05」라는 **2026년 8월 이전의 더미 계산식**을 씁니다.
김천 중학생 3,200명 × 0.05 = 160명 — 이 160명이 그대로 화면에 올라옵니다.

### 왜 검사에 안 걸렸나 ← 이 부분이 더 중요합니다

자체 검사에 **「시군별로 쪼개서 세도 합계가 맞는가」** 라는 딱 맞는 검사가 이미 있습니다.
그런데 그 검사가 **초·중·고 세 학교급만 돕니다.** 유치원과 특수학교는 빠져 있습니다.

```
for (const lv of ['초','중','고']) { ... }   ← 5개 중 3개만
```

**검사 170개가 전부 초록인 채로 이 오류가 라이브에 있었습니다.**
회의에서 이 점을 공유하세요 — 「검사가 초록이니 괜찮다」가 항상 참은 아니라는 실물 사례입니다.

### 고치는 법

두 줄이면 됩니다. `학교수 === 0`이면 학생·학급·학교 전부 **0**으로 두면 됩니다.
그리고 검사의 `['초','중','고']`를 `['초','중','고','유','특수']`로 넓힙니다.

| **「특수교육 대상자」** | **6,902명** | **5,382명** | **1,520명** |

# 3. 질문 3건 — 확인 결과

## ① 뉴스 — **고장이 아니었습니다** 〔이전 보고 정정〕

첫 점검에서 「최신 기사가 8월 26일, 11일째 그대로」라고 적었습니다. **그것은 제 착오였습니다.**
날짜를 글자순으로 정렬해서 `Wed, 26 Aug` 가 `Mon, 31 Aug` 뒤로 갔던 것입니다.

**실제로는 8월 31일까지 끊김 없이 들어와 있습니다.**

```
8/22(2)  8/23(12)  8/24(6)  8/25(17)  8/26(13)
8/27(11) 8/28(9)   8/29(2)  8/30(4)   8/31(2)      ← 총 137건
```

GitHub Actions에 실패 기록이 없던 것도 당연합니다 — **아무것도 실패하지 않았습니다.**

| | |
|---|---|
| 주간 일정 | `0 22 * * 0` = 일요일 22시(UTC) = **월요일 07시(한국)** |
| 마지막 수집 | **8월 31일(월)** — 그날 아침 정상 수행 |
| 8/31 저녁에 바뀐 것 | `if: github.event_name != 'push'` 가 들어갔습니다. 그전에는 push 때마다 뉴스를 받아 히스토리가 17일치 → 8일치로 줄었습니다. 그 부작용을 막은 **옳은 수정**입니다 |
| 그 뒤 첫 일요일 | **바로 오늘(9/6)** — 오늘 밤 22시(UTC)에 돕니다 |
| 다음 갱신 | **9월 7일(월) 아침 7시** |

> **결론: 손댈 것이 없습니다.** 다만 8월 31일 이후로 «일정»이 실제로 도는 것을 아직 본 적이 없습니다
> (그전에는 push 갱신에 가려 보이지 않았습니다).
> **9월 7일 월요일 아침에 Actions 에서 `Event: schedule` 실행이 생겼는지 한 번만 확인해 주세요.**

## ② 예천 — **진짜 문제였고, 예천만의 문제도 아니었습니다** 〔수정 완료〕

「도청신도시 영향이면 맞는 값」이라고 적었는데, 자료를 열어 보니 **그 설명으로는 부족했습니다.**

```
예천 초등학생   1,437 → 1,377 → 1,326 → 1,870 → 2,088 → 2,212 → 2,298 → 2,310 → 2,217 → 2,067
                2016                        2019↑         신도시 입주        2023 정점 ↓  ↓  2025
```

2019년에 **한 번** 뛰었고, **2023년부터는 내리 줄고 있습니다.**
그런데 감소율을 **10년 전체(2016~2025)** 로 재고 있었습니다. 그러면 신도시 입주 한 번이
「해마다 +4.12%씩 계속 는다」로 바뀌고, 그것을 2030년까지 곱해 **+12.6%** 가 나온 것입니다.

**여기가 중요합니다 — 예천만의 문제가 아니었습니다.**

| 시군 | 10년 평균 | 최근 5년 | 시군 | 10년 평균 | 최근 5년 |
|---|---|---|---|---|---|
| 포항 | −1.11%/년 | **−3.38%** | 구미 | −1.11%/년 | **−3.25%** |
| 경산 | −0.67%/년 | **−3.05%** | 칠곡 | −2.95%/년 | **−5.63%** |
| 김천 | −0.58%/년 | **−3.15%** | 울릉 | −5.37%/년 | **−9.51%** |

**22개 시군 전부** 최근 감소가 10년 평균보다 가파릅니다. 감소가 **빨라지고 있는데**
10년 평균이 그것을 눌러 평평하게 만들고 있었습니다.
**학령인구 감소에 대응하려고 만든 화면이 감소를 작게 말하고 있었습니다.**

→ 감소율 산출 구간을 **최근 5개 연도**로 좁혔습니다 (`bake-edss.mjs` + 심어진 값 재계산).

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 예천 초등 2030 | 1,958 → **2,204 (+12.6%)** | 1,958 → **1,830 (−6.5%)** |
| 경북 초등 전체 2030 | 101,176 → 94,708 (−6.4%) | 101,176 → **86,448 (−14.6%)** |
| 증가로 전망되는 시군 | 1곳 (예천) | **0곳** |

> **회의에서 확인받을 것**: 「최근 5년」이 맞는 구간인지. 짧으면 한 해 통폐합에 흔들리고,
> 길면 신도시 같은 한 번뿐인 사건에 끌려갑니다. **데이터팀 의견이 필요합니다.**

**어디서 보나** — 왼쪽 메뉴 **「학생수 시뮬레이터」** → 시군 「전체」 · 학교급 「초등학교」 ·
모의연도 「2030」 → 오른쪽 표의 **「대비 감소율」** 칸. 예천 줄이 빨간 음수(−12.6)였던 자리입니다.

## ③ 좌표 — **포항해오름중학교 한 곳뿐이 맞았습니다** 〔수정 완료〕

917곳을 한 줄씩 다시 세었습니다. **좌표가 빠진 곳은 그 학교 하나뿐**이었고,
유치원 614곳·특수학교 8곳은 모두 좌표가 있었습니다. 경북 범위를 벗어난 좌표도 0건입니다.

**왜 그 학교만인가** — 「신설교라서」가 아닙니다. 초·중·고 좌표는 **학교알리미 API**가 직접 줍니다
(유치원만 주소를 좌표로 바꿔 씁니다). 그런데 학교알리미가 **그 학교 레코드에만 위경도를 비워서**
보내고 있었습니다. 굽는 코드에 `위경도가 없으면 건너뛴다`가 있어 조용히 빠졌습니다.
같은 날 개교한 **포항펜타초등학교는 좌표가 와서** 들어가 있었습니다 — 개교일 문제가 아니라
**그 학교 레코드만** 비어 있던 것입니다.

→ 주소(`남구 오천읍 하원로26번길 20-11`)를 카카오로 찾아 **35.9730, 129.4076** 을 채웠습니다.
→ 다시는 조용히 빠지지 않게, `bake-coords.mjs` 에 **주소로 찾는 폴백**을 넣었습니다
   (유치원에 쓰던 것과 같은 방법). 못 찾으면 여전히 **비워 둡니다** — 아무 데나 찍지 않습니다.
→ 검사 문턱도 「빠진 곳 1곳」에서 **「빠진 곳 없음」**으로 올렸습니다.

## ④ EDSS — **모두 승인된 것이 맞았습니다** 〔수정 완료〕

말씀대로였습니다. 7개 API 전부 승인되어 **8월 31일부터 실제로 굽고 있습니다**

곁들여 하나 더 찾았습니다. 상태 API가 **엉뚱한 곳을 보고 있었습니다.**
학교알리미·KOSIS·유치원알리미 열쇠는 **GitHub Actions 시크릿**에 있는데,
이 함수는 **Cloudflare 배포 환경**만 볼 수 있어 「미설정」이라고 답하고 있었습니다.
밖에서 보면 자동 갱신이 꺼진 것처럼 보였습니다.

→ 런타임에 쓰는 것(Gemini·SGIS)만 배포 환경에서 확인하고,
   수집용은 **`managed_in_actions`(여기서는 알 수 없음)** 으로 정직하게 답하도록 고쳤습니다.
   **모르는 것을 「없다」로 적지 않습니다.**

## ⑤ 지도 이동 — **만들었습니다** 〔신규 기능〕

목록에 이름이 보여도 그 학교가 어디 있는지는 지도를 눈으로 훑어 찾아야 했습니다.
이제 **목록에서 학교를 누르면 지도가 그 학교로 갑니다.**

| | 동작 |
|---|---|
| **실제 위치 지도** | 그 학교로 이동 + 확대(3 → 7) + 묶음이 풀릴 때까지 더 확대 + **말풍선 자동 열림** |
| **간편 지도** | 그 학교로 이동 + 2.6배 확대 + **핀이 잠깐 깜빡여 어디인지 알려 줌** |
| 시군을 아직 안 골랐을 때 | 그 학교의 **시군을 먼저 펼친 뒤** 이동 |
| 좌표가 없는 학교 | 지도를 흔들지 않고 **「좌표가 없어 표시할 수 없습니다」**라고 말함 |

`<div>`가 아니라 **진짜 `<button>`** 으로 만들었습니다 — 키보드(Tab·Enter)로도 됩니다.
`prefers-reduced-motion` 을 켠 사람에게는 깜빡임과 움직임을 끕니다.

# 5. 디자인팀과 논의할 것

## 5-1. 【최우선】 추세선이 실적과 추계를 구분하지 않습니다

「경북 학령인구 현황」의 연도별 추이 선그래프는 2016~2036년을 **하나의 실선**으로 그립니다.

- 2016~2025 = **실제로 일어난 일** (주민등록 실적)
- 2026~2036 = **아직 안 일어난 일** (장래인구추계)

**둘이 똑같이 굵은 파란 실선입니다.** 「현재」 세로 점선 하나만 있습니다.
데이터 시각화에서 **추계 구간은 점선이나 옅은 색으로 구분하는 것이 원칙**입니다.
지금은 2036년 144천명이 실적처럼 보입니다.

> **요청**: 2026년 이후 구간을 **점선 + 옅은 색**으로. 가능하면 추계 구간에 **신뢰 밴드**.

## 5-2. 학년별 막대가 감소를 「증가」처럼 보이게 합니다

「2026 학년별 학생 분포」는 초1부터 고3까지 세로로 나열되는데, 값이 이렇습니다.

```
초1  12,765  ▬▬▬▬▬▬▬▬▬▬▬▬▬
초2  14,158  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬
...
고3  20,464  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬
```

**아래로 갈수록 막대가 길어집니다.** 사람은 이걸 「늘고 있다」로 읽습니다.
실제 뜻은 정반대 — **어린 학년일수록 적다 = 학령인구가 줄고 있다**는,
이 대시보드에서 가장 강력한 증거입니다. 그런데 그림이 반대로 말하고 있습니다.

> **요청**: 고3을 위에 두거나, 인구 피라미드 형태로 바꾸거나,
> **「초1이 고3보다 7,699명(38%) 적습니다」** 같은 한 줄을 그림 위에 붙이기.

## 5-3. 모바일에서 메뉴가 화면 두 개를 차지합니다
