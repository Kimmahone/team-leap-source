# 주간 뉴스 클리핑 → 뉴스 분석 — 실행계획

작성: 2026-09-10 · 대상: 대시보드 「주간 뉴스 클리핑」 화면
바탕: `00. 학령인구감소/뉴스 크롤링/` (다른 곳에서 만든 빅카인즈 파이프라인)
회의 근거: 9/9 GBE-AI 연구원(2기) — 「빈도 분석 · 워드클라우드 · 다빈도 키워드 ·
벡터화 · 유사도 카테고리화 · 시군별 크롤링 · 이슈페이퍼」

## 0. 결론 먼저

1. **가져온 파이프라인이 지금 화면보다 훨씬 앞서 있습니다.** 10개년 · 19,980건입니다.
2. 다만 **그대로 심을 수는 없습니다.** 자료가 22MB 라 단일 HTML 에 들어가지 않습니다.
3. **자료를 잘라 나누고, 화면은 필요할 때만 불러오는 방식**으로 붙입니다.
4. 이슈페이퍼는 **없습니다.** 이번에 새로 만듭니다.

교원·정원 / 교육재정 / 통학·돌봄. 이어 붙이기 좋은 조건입니다.

## 2. ★ 가장 큰 제약 — 크기

```
output/news-entities.json      15.0 MB
output/news-history-all.json   14.9 MB
output/news-history.json        7.2 MB
output/network-data.json        1.4 MB
output/wordcloud-data.json       63 KB
                               ───────
                                38.6 MB
```

대시보드 `index.html` 은 지금 **약 760KB** 입니다. 통째로 심으면 50배가 됩니다.
열리지 않습니다.

### 2-1. 그래서 어떻게 하나 — 「굽기」에서 「나눠 두고 불러오기」로

`/dashboard/*` 의 CSP 는 `connect-src 'self'` 입니다. **같은 출처 파일은 부를 수
있습니다.** 이미 `/api/ai-analysis` 와 `/api/vworld-key` 를 그렇게 부릅니다.

| 무엇 | 어디에 | 언제 부르나 |
|---|---|---|
| 워드클라우드 (63KB) | 인라인 | 화면과 함께 |
| 연도별 요약·주제별 건수 (새로 만듦, ~30KB) | 인라인 | 화면과 함께 |
| 관계망 (1.4MB) | `/dashboard/data/network.json` | 「관계망 보기」를 누를 때 |
| 기사 목록 | `/dashboard/data/news-YYYY.json` **연도별로 쪼갬** | 그 연도를 고를 때 |
| 개체명 15MB | **싣지 않습니다** | — |

**개체명 원본은 싣지 않습니다.** 화면이 쓰는 것은 «집계된 키워드»이지 기사마다의
개체명이 아닙니다. 워드클라우드와 관계망을 만들 때 이미 쓰였습니다. 원본은
저장소에 두고 필요하면 다시 굽습니다 — 사본은 조용히 낡습니다.

## 3. 화면 구성 (안)

지금 한 화면에 다 넣지 않고 **탭 셋**으로 나눕니다.

### 3-1. 「이번 주」 (지금 화면 유지)

네이버 API 로 매주 들어오는 최신 기사. 지금 그대로 둡니다.
**빅카인즈는 과거 아카이브, 네이버는 최신** — 역할이 다릅니다.

### 3-2. 「10년 흐름」 (새로 만듦)

- **연도별 기사량 막대** 2016~2026 — 어느 해에 이야기가 몰렸는가
- **주제별 비중 변화** — 통폐합 이야기가 언제부터 늘었는가
- **워드클라우드** — 전체 / 연도 / 주제로 갈아 끼움
- **다빈도 키워드 표** — 순위·건수·전년 대비 증감

> ★ 여기서 지킬 것: **기사량은 «관심»이지 «사실»이 아닙니다.**
> 폐교 기사가 는 것과 폐교가 는 것은 다릅니다. 학생 수 실적선을 같은 그림에
> 겹쳐 두되, **인과로 읽지 않도록** 화면이 그렇게 적어야 합니다.

### 3-3. 「이슈페이퍼」 (새로 만듦 · 회의 요청 사항)

기사 다발을 묶어 한 장으로 정리한 것. 저장소에 파일로 쌓고 화면이 목록으로 보여 줍니다.

한 장에 들어갈 것 —
- 제목 · 기간 · 주제
- **근거 기사 목록** (제목·언론사·날짜·링크만. 본문은 저장하지 않습니다)
- 핵심 키워드
- 우리가 쓴 요약
- **학령인구 자료와 맞대본 한 줄** (예: 「이 시기 이 시군 초등학생은 N% 줄었습니다」)
- 검토자 · 발행일

만드는 방식은 **두 층**입니다.
- **아래층(규칙)** — 어느 기사 다발인지, 키워드 빈도, 기간, 시군은 셈으로 냅니다
- **위층(모델)** — Gemini 가 «문장»만 씁니다. 사람이 검토한 뒤에 발행합니다

> **숫자는 규칙이 내고 문장만 모델이 냅니다.** 모델이 숫자를 만들면 검증할 수
> 없습니다. 이 프로젝트가 지어낸 숫자로 이미 여러 번 되돌린 자리입니다.

## 4. 회의에서 요청한 것과의 대응

| 회의 요청 | 어디서 오나 | 새로 할 일 |
|---|---|---|
| 빈도 분석 | 파이프라인에 **있음** | 화면만 만들면 됨 |
| 워드클라우드 | **있음** (전체·연도·주제) | 그리는 코드 |
| 다빈도 키워드 | **있음** | 표로 |
| 벡터화·유사도 카테고리화 | **부분** — 관계망(공출현)은 있음 | TF-IDF 로 기사 묶기는 새로 |
| 시군별 크롤링 | **부분** — 개체명에 장소가 있음 | 시군별 집계·화면 |
| 이슈페이퍼 | **없음** | 전부 새로 |

### 4-1. 「벡터화」에 대하여

회의에서 나온 말은 «기사를 벡터로 바꿔 유사한 것끼리 묶자»입니다.
가져온 관계망은 **키워드 공출현**이라 성격이 다릅니다 — 둘 다 필요합니다.

기사 묶기는 **TF-IDF + 코사인 유사도**로 합니다. 순수 자바스크립트로 되고
외부 라이브러리가 필요 없습니다. 굽는 단계에서 미리 묶어 두고 화면은 결과만
그립니다 — 화면이 실행 중에 19,980건을 셀 수는 없습니다.

## 5. 단계와 크기

| 단계 | 무엇 | 크기 |
|---|---|---|
| **1** | 자료 쪼개기 — 연도별 기사 파일 · 요약 인라인 블록 굽는 스크립트 | 1.5일 |
| **2** | 「10년 흐름」 탭 — 연도별 막대 · 주제 비중 · 워드클라우드 | 2일 |
| **3** | 다빈도 키워드 표 · 시군별 집계 | 1일 |
| **4** | 관계망 보기 (누를 때 불러오기) | 1.5일 |
| **5** | TF-IDF 기사 묶기 (굽는 단계) | 1일 |
| **6** | 「이슈페이퍼」 목록·상세 화면 + 저장 규약 | 2일 |
| **7** | 이슈페이퍼 초안 생성 (Gemini) + 검토 절차 | 1.5일 |

1~4 만 해도 회의에서 요청한 「한눈에 보이게」는 채워집니다.
5~7 이 「이슈페이퍼」입니다.

## 6. 먼저 정해야 할 것

1. **빅카인즈 자료를 저장소에 넣을 것인가.**
   연도별로 쪼개도 합쳐서 7MB 안팎입니다. 저장소가 그만큼 무거워집니다.
   넣지 않으려면 굽는 단계에서 «집계만» 뽑고 기사 목록은 최근 것만 둡니다.
2. **어느 아카이브를 쓸 것인가** — 큐레이션 9,538건 / 전체 19,980건.
   전체에는 「학폭 피해 9만명」처럼 학령인구와 먼 기사가 섞여 있습니다.
   화면에는 **큐레이션**을, 집계에는 전체를 쓰는 쪽을 권합니다.
3. **이슈페이퍼를 누가 검토하고 발행하는가.** 사람 손이 반드시 한 번 들어갑니다.
4. **저작권** — 지금 규칙(제목·언론사·날짜·링크·자체 요약만) 그대로 갑니다.
   빅카인즈 본문은 저장하지 않습니다.

## 7. 미리 적어 두는 함정

- **기사량은 관심이지 사실이 아닙니다.** 시군별 기사량을 학생 수 변화 옆에 두면
  사람은 인과로 읽습니다. 화면이 「이 시군에 이런 이야기가 얼마나 오르내렸나」
  까지만 말해야 합니다.
- **언론사 구성이 해마다 다릅니다.** 빅카인즈에 들어온 매체가 늘면 기사량도 늡니다.
  연도별 비교는 그 사실을 함께 적어야 합니다.
- **개체명은 자동 추출입니다.** 「포항」이 지명인지 학교 이름의 일부인지 가리지
  못합니다. 워드클라우드에 사람 이름이 섞이는 것도 그래서입니다.
- **19,980건을 화면에서 세지 않습니다.** 굽는 단계에서 끝내고 화면은 결과만 그립니다.
