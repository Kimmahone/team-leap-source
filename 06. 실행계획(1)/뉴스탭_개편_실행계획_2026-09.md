### ★ 2024년이 3,137건으로 튀는 것을 그대로 보여 주면 안 됩니다

**언론사 구성이 해마다 다릅니다.** 빅카인즈에 들어온 매체가 늘면 기사량도 늡니다.
2016년 1,176건에서 2024년 3,137건으로 «2.7배»가 된 것을 그대로 그리면
「학령인구 이야기가 2.7배 늘었다」로 읽힙니다. 그것은 사실이 아닐 수 있습니다.

> **그래서 연도 비교는 «건수»가 아니라 «비중»으로 합니다.**
> 그 해 경북 교육 기사 가운데 학령인구 주제가 몇 %인가. 분모가 함께 커지므로
> 매체 구성 변화에 덜 흔들립니다. 건수는 곁에 작게 적되, 매체 수가 해마다
> 다르다는 것을 화면이 함께 말합니다.

## 1. 전체 19,980건으로 가는 것의 뜻

| | 뜻 |
|---|---|
| 좋은 점 | 분모가 생깁니다. 「경북 교육 기사 중 학령인구 이야기가 몇 %」를 말할 수 있습니다 |
| 좋은 점 | 주제 밖 기사에도 시군·기관 이름이 있어 **시군별 집계**가 두터워집니다 |
| 조심할 점 | 「학폭 피해 9만명」처럼 **학령인구와 먼 기사가 섞여 있습니다** |

### 그래서 화면을 이렇게 가릅니다

- **기본 화면은 「학령인구 6대 주제」(9,538건)** 입니다. 목록·워드클라우드·관계망 모두.
- **「경북 교육 전체(19,980건)」는 켜는 것**입니다. 껐다 켤 수 있는 단추 하나.
- **분모로 쓸 때는 언제나 전체**입니다 — 비중을 낼 때가 그렇습니다.

이러면 「전체를 쓴다」와 「엉뚱한 기사를 보여 주지 않는다」가 함께 섭니다.
화면에는 **지금 무엇을 보고 있는지**를 늘 적습니다.

## 2. 백엔드 담당자에게 넘기는 법 〔새로 정한 것〕

### 2-1. 저장소에 넣을 것과 넣지 않을 것

| | 크기 | 저장소 | 왜 |
|---|---|---|---|
| 파이프라인 스크립트·README | 작음 | **넣음** | 이것이 «만드는 법»입니다 |
| `wordcloud-data.json` | 63KB | **넣음** | 화면이 바로 씁니다 |
| `network-data.json` | 1.4MB | **넣음** | 누를 때 불러옵니다 |
| 연도별로 쪼갠 기사 목록 | 합 ~7MB | **넣음** | 화면이 연도별로 불러옵니다 |
| `news-entities.json` | 15MB | **안 넣음** | 화면이 쓰지 않습니다. DB 로 갑니다 |
| `news-history-all.json` | 15MB | **안 넣음** | 위 연도별 쪼갠 것과 겹칩니다 |
| 빅카인즈 원본 `.xlsx` 11개 | 수십MB | **안 넣음** | 다시 받을 수 있습니다 |

### 2-2. 원본은 어떻게 넘기나

**깃에 넣지 않습니다.** 이유가 셋입니다 — 저장소가 무거워지고, 빅카인즈
이용약관이 재배포를 제한할 수 있으며, 어차피 **다시 받을 수 있는 것**입니다.

넘기는 방법 —

1. **원본 `.xlsx` 는 구글 드라이브(또는 노션)로.** 팀원이 한 번 받아 DB 에 적재합니다.
2. **`README.md` 의 검색식을 함께 줍니다.** 이것이 곧 «어떻게 뽑았는가»입니다.
   같은 검색식으로 다시 받으면 같은 자료가 나옵니다. 사본보다 이것이 원본입니다.
3. **스키마 문서(`뉴스_자료_스키마.md`)를 새로 씁니다.** 아래 표가 그 뼈대입니다.

### 2-3. 팀원에게 줄 표 모양 (DB 설계의 출발점)

```
news                     기사 하나 = 한 줄
  id            문자열   링크의 해시. 같은 기사가 여러 번 들어와도 하나
  title         문자열
  press         문자열   언론사
  published_at  날짜
  link          문자열   원문 주소
  summary       문자열   빅카인즈 본문 앞부분 (본문 전체는 저장하지 않음)

news_topic               한 기사가 여러 주제에 걸칠 수 있어 따로 둡니다
  news_id, topic         topic ∈ 6대 주제

news_entity              개체명. 화면은 안 쓰고 분석이 씁니다
  news_id, kind, value   kind ∈ 장소 · 기관 · 인물 · 키워드

news_region              시군 집계용
  news_id, sigungu       경북 22개 시군 중 본문에 나온 것
```

> **소수값·중복 주의** — 링크가 다르지만 같은 기사(전재)가 있습니다. `id` 를
> 링크 해시로 잡으면 못 거릅니다. 제목+발행일+언론사로 한 번 더 봐야 합니다.
> 지금 파이프라인이 중복을 어떻게 걸렀는지 팀원에게 알려 줘야 합니다.

## 4. 이슈페이퍼 — 프로토타입 설계 〔새로 정한 것〕

**지금 목표는 프로토타입입니다.** 그래서 **백엔드 없이 시작합니다.**

### 4-1. 1단계 (지금) — 파일과 PR 로 돕니다

```
06. 실행계획(1)/issues/
  2026-09-2주-통폐합.json      ← 이슈페이퍼 한 장
  2026-09-1주-교육발전특구.json
```

| 무엇 | 누가 |
|---|---|
| 초안 만들기 | 굽는 스크립트 (숫자) + Gemini (문장) |
| 검토 | **PR 로** — 사람이 읽고 고친 뒤 머지 |
| 발행 | 머지되면 화면에 뜸 |

**검토자를 지금 정하지 않아도 됩니다.** PR 을 여는 것이 곧 「검토해 주세요」이고,
머지가 곧 발행입니다. 저장소가 이미 그 일을 하고 있습니다.

### 4-2. 2단계 (백엔드가 붙은 뒤) — 마스터 계정

팀원이 DB·백엔드를 세우면 그때 옮깁니다.

```
초안 생성(배치) → 상태: 검토대기
      ↓ 마스터 계정으로 로그인해 읽고 고침
   상태: 발행     → 화면에 뜸
   상태: 보류/폐기 → 안 뜸. 까닭을 남김
```

- 화면은 **발행된 것만** 부릅니다. 검토 화면은 로그인 뒤에만 열립니다.
- 1단계의 JSON 모양을 그대로 테이블로 옮기면 됩니다 (아래).

### 4-3. 이슈페이퍼 한 장의 모양 (1·2단계 공통)

```
id            2026-09-2주-통폐합
기간          2026-09-07 ~ 2026-09-13
주제          통폐합·적정규모
제목          사람이 씁니다 (초안은 모델)
요약          3~5문장. 모델이 쓰고 사람이 고칩니다
핵심키워드    ["적정규모","분교장","통학버스", …]     ← 셈으로 냅니다
근거기사      [{제목, 언론사, 날짜, 링크}]             ← 본문은 저장하지 않습니다
데이터_대조   "이 시기 의성군 초등학생은 전년 대비 6.1% 줄었습니다"  ← 셈으로 냅니다
상태          검토대기 | 발행 | 보류
검토자        (2단계부터)
발행일
```

### 4-4. 두 층으로 만듭니다 — 이것이 핵심입니다

- **아래층(규칙)** — 기사 다발 고르기 · 키워드 빈도 · 기간 · 시군 · 학생 수 대조
- **위층(모델)** — Gemini 가 **문장만** 씁니다

> **숫자는 규칙이 내고 문장만 모델이 냅니다.** 모델이 숫자를 만들면 검증할 수
> 없습니다. 이 프로젝트가 지어낸 숫자로 이미 여러 번 되돌린 자리입니다.
> 화면에는 「이 글의 문장은 AI 초안을 사람이 검토한 것」이라고 적습니다.

## 5. 저작권 〔지금 규칙 그대로〕

## 7. 미리 적어 두는 함정

- **연도별 건수를 그대로 비교하지 않습니다.** 매체 구성이 해마다 다릅니다.
- **기사량은 관심이지 사실이 아닙니다.** 시군별 기사량을 학생 수 옆에 두면
  사람은 인과로 읽습니다.
- **개체명은 자동 추출입니다.** 「포항」이 지명인지 학교 이름의 일부인지 가리지
  못합니다. 워드클라우드에 사람 이름이 섞이는 것도 그래서입니다.
- **19,980건을 화면에서 세지 않습니다.** 굽는 단계에서 끝내고 화면은 결과만 그립니다.
- **전재 기사가 있습니다.** 링크가 달라도 같은 기사입니다. 중복 제거 규칙을
  팀원에게 반드시 알려 줘야 합니다.
