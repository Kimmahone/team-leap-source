## 2. 새 사이트 설정 (9. 26. 완료 — 브이월드 도메인 등록·키 입력)

Cloudflare → Workers & Pages → **team-leap-v2** → Settings → Variables and Secrets (Production) 에 Secret 으로:

| 이름 | 없으면 |
|---|---|
| `VWORLD_API_KEY` | 지도 배경(위성·지명)이 비고 «배경지도 없음»이 뜸 — 학교·경계는 보임 |
| `GEMINI_API_KEY` | 시뮬레이터 «AI 인사이트»가 안 됨 |
| `SGIS_CONSUMER_KEY` (선택) | 옛 SGIS 지도 스크립트만 영향 |

넣은 뒤 Deployments → 최신 배포 → **Retry deployment**. 그리고 **브이월드(vworld.kr) 키 설정에 `team-leap-v2.pages.dev` 도메인을 추가**해야 배경지도가 나옵니다(브이월드는 등록한 도메인에서만 답합니다).

## 3. 깃허브 · 다시 배포하는 법

저장소는 **하나(team-leap-source)** 그대로입니다. 새 판은 그 안의 **`v2` 가지**입니다.

```
main ─▶ update-news.yml · deploy.sh ─▶ 저장소 team-leap ─▶ team-leap.pages.dev   (기존 사이트, 그대로)
v2   ─▶ v2-deploy.yml ─(wrangler)──────────────────────▶ team-leap-v2.pages.dev (새 판)
```

- **v2 에 푸시하면** 검사 → 굽기 → team-leap-v2 배포가 저절로 됩니다.
- **손으로 다시 배포**: GitHub → Actions → 「새 판(v2) — 검사·굽기·배포」 → Run workflow → 가지 `v2`, job 고르기
  (`deploy` 그대로 · `daily` 뉴스 새로 받고 · `weekly` 주간 브리프 한 호 만들고).
- **예약**: 매일 07:47(뉴스) · 월요일 05:17(주간 브리프). GitHub 는 예약과 「Run workflow」 단추를 기본 가지(main)에 있는
  파일로만 돌리므로 **같은 `v2-deploy.yml` 을 main 에도 둡니다.** main 에서는 v2 쪽을 불러 줄 뿐 아무것도 배포하지 않습니다.
- 기존 사이트 보호: `deploy.sh` 는 main 이 아니면 멈춥니다. `v2-deploy.yml` 은 v2 에서만 돕니다.
- 깃허브 시크릿: `CLOUDFLARE_API_TOKEN`(Pages 편집 권한) · `CLOUDFLARE_ACCOUNT_ID` · `GEMINI_API_KEY`(없으면 브리프는 규칙 초안).

컴퓨터에서 바로 올릴 때(비상용):

```bash
cd "00. 학령인구감소/1-1. 로컬 실험 (디자인 틀·주간 브리프)"
bash "사이트 굽기.command"          # 검사 → 굽기 (배포/site)
npx wrangler pages deploy "배포/site" --project-name=team-leap-v2 --branch=main
```

`wrangler` 는 **이 폴더(맨 위)에서** 돌려야 `functions/`(지도 키·AI 중계)가 함께 올라갑니다.
