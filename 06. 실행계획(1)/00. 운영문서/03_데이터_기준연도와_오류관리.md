# 데이터 기준연도와 오류 관리

## 기준연도 관리 원칙

각 데이터에는 다음 네 시점을 구분해 기록합니다.

| 항목 | 뜻 | 예시 |
|---|---|---|
| `referenceDate` | 수치가 설명하는 기준연도·공시차수 | `2026 공시` |
| `publishedAt` | 제공기관이 공개·개정한 날 | `2026-08-20` |
| `fetchedAt` | 시스템이 API를 수집한 시각 | ISO 날짜·시간 |
| `catalogVersion` | 대시보드가 쓰는 데이터 목록 버전 | `2026-08-29.1` |

수집일이 최신이라고 기준연도까지 최신인 것은 아닙니다. 화면에는 `2026년 자료`처럼 기준연도를 표시하고, 운영 상태에는 별도로 마지막 수집일을 기록합니다.

## 데이터별 기준연도

| 데이터 | 현재 기준 | 갱신 판단 |
|---|---|---|
| 학교·학생·학급·교원 | 학교알리미 2026 공시 | 새 공시연도 확인 후 `PUBLIC_DATA_YEAR` 변경 |
| 유치원 | 기관별 2023-2차~2026-1차 최신 공시 | 새 공시차수가 실제 응답에 포함될 때 갱신 |
| KOSIS 주민등록 학령인구 | 2016~2025 실적 | KOSIS 최근 연도 증가 또는 과거값 개정 시 |
| KOSIS 장래인구 | 2026~2036 장래인구 | 통계표 개편·추계 기준 변경 시 |
| 학교 좌표 | 2026-08-26 수집 | 개폐교·주소 변경·좌표 누락 변화 시 |
| 최신 뉴스 | 매일 최신 | 매일 오전 7시 37분 수집 시 |
| 이슈 분석·이슈페이퍼 | 최근 30일 비교·최근 7일 요약 | 마지막 생성일로부터 3일 후 |

`PUBLIC_DATA_YEAR`는 GitHub 저장소의 Actions Variable로 관리합니다. 새 공시가 실제로 제공된 것을 확인한 뒤에만 다음 연도로 바꿉니다.

## 공개 전 품질검사

새 자료는 다음 조건을 모두 통과해야 합니다.

1. 응답 행 수가 0이 아니고 전년 대비 비정상 급감이 없음
2. 공식 학교코드·시군코드·학교급이 누락되지 않음
3. 같은 학교·기준연도 데이터가 중복되지 않음
4. 학생수·학급수·학교수 합계가 원자료와 일치
5. 좌표가 경북 범위 안에 있고 시군 중심에서 과도하게 벗어나지 않음
6. 기준연도와 실제 응답의 공시연도가 일치
7. 전체 자동검사와 키 유출 검사를 통과

하나라도 실패하면 새 자료를 커밋·배포하지 않고 직전 정상 데이터를 유지합니다.

## 오류 등급

| 등급 | 예 | 공개 처리 |
|---|---|---|
| 안내 | 일부 선택 기능의 무료 사용량 초과 | 해당 기능만 기본 요약으로 전환 |
| 주의 | 일부 학교 좌표 누락, 제공기관 일시 장애 | 직전 정상값 유지·운영 기록 |
| 차단 | 행 수 0, 합계 급변, 스키마 변경, 기준연도 불일치 | 배포 중단·원인 확인 |
| 보안 | 키 노출, 비인가 요청, 비밀값 로그 | 키 폐기·재발급·로그 점검 |
