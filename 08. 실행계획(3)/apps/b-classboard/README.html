왜 이 앱인가

소규모 학급은 인원이 적어 익명이 성립하지 않습니다. 6명 학급에서 손을 들면 누가 무슨 의견인지 다 보입니다. 그래서 무기명 도구가 대규모 학급보다 오히려 절실합니다.

이 논리가 앱과 "학령인구 감소 대응"을 잇습니다. 학령인구가 줄어 학급이 작아질수록 이 도구가 더 필요해집니다.

무기명을 지키는 다섯 가지 (설계에 박아 넣은 것)

기능이 아니라 구조입니다. 끄거나 우회할 수 없습니다.

#장치없으면 생기는 일

2제출 시각을 저장하지 않는다시각 순서로 누가 냈는지 역추적된다

4번은 Fisher-Yates로 섞고, 가능하면 crypto.getRandomValues를 씁니다.

진행 방식

교실 기기 한 대를 돌려가며 씁니다. 다섯 단계입니다.

1. 안건 모으기   무기명 제출 → 개수만 표시
        ↓ [모으기 마치고 공개]  ← 여기서 순서를 섞는다
2. 안건 고르기   한 사람씩 택1 → 집계 감춤
        ↓ [투표 마치고 결과 보기]
   결과 공개 → 다룰 안건 선택 (동점이면 함께 정함)
        ↓
3. 해결책 모으기  같은 방식
4. 해결책 고르기  같은 방식
5. 결정          결정문 작성 → 학급 약속으로 등록

각 단계마다 제출·투표 뒤 입력창이 즉시 비워지고 "다음 사람에게 넘겨 주세요"가 뜹니다.

기기를 여러 대 쓸 때

각자 기기에서 같은 회의를 열고, 끝나면 파일로 내보내기 → 한 기기에서 가져오기 → 합치기를 고르면 안건과 투표가 더해집니다. 회의 id가 같을 때만 합쳐집니다.

실시간은 어디까지 되는가 〔v0.4〕

다른 기기와는 실시간이 되지 않습니다. 브라우저는 같은 랜 안의 다른 기기를 스스로 찾지 못합니다. WebRTC 로 기기끼리 직접 잇더라도 상대를 찾아 주는 일(시그널링)은 서버가 합니다. 서버를 두지 않는 것이 이 앱들의 약속입니다(마스터 원칙 1·2번). 그러니 태블릿 여섯 대에 같은 주소를 띄워 놓고 서로 보이기를 기대하면 안 됩니다.

되는 것은 같은 브라우저의 다른 창입니다. 그리고 그 자리는 실제로 있습니다 — 교사는 노트북에서 회의를 돌리고, 빔프로젝터에는 모아 보기 창을 띄웁니다.

어디서 여나모으는 화면·투표 화면의 「모아 보기 창 열기」
무엇이 뜨나회의 이름 · 지금 단계 · 모인 개수(인원을 적었으면 「4 / 6」)
무엇이 안 뜨나낸 내용, 어느 것이 몇 표인지. 이 화면에 내용이 뜨면 무기명이 그 자리에서 무너집니다
어떻게 이어지나BroadcastChannel · storage 이벤트 · 2초마다 스스로 확인(셋 다 두는 것은 file:// 로 열면 앞의 둘이 막히는 브라우저가 있기 때문입니다)
쓰기는 하나읽기만 합니다. 빔프로젝터에 띄워 둔 창이 회의 자료를 건드릴 길이 없어야 합니다

같은 파일을 #board 로 열면 켜집니다. 파일이 하나여야 한다는 약속을 지키면서 창을 둘로 쓰는 방법입니다.

검사가 이것을 고정합니다 — 「모아 보기 창에 안건 내용이 나가지 않는다」, 「투표 중 집계가 나가지 않는다」.

색을 쓸 때 주의한 것

화려하게와 접근성이 부딪히는 지점이 있었습니다. 다듬는 중에 네 곳이 대비 기준 미달로 걸렸습니다.

접근성

12월 웹앱스토어 등록 조건에 맞춰 처음부터 넣었습니다.

  • 색만으로 정보를 전달하지 않음 — 신호등은 색 + 글자 병기
  • 전체 키보드 조작 가능. 탭은 좌우 화살표로 이동
  • 포커스 표시 3px, 버튼 최소 높이 46px
  • 제출·투표 결과를 role="status"로 읽어 줌
  • 단계 궤적 그림은 role="presentation", 대신 숨은 목록으로 단계·진행 상태를 읽어 줌
  • 의미 있는 마크업 (nav, main, role="tablist", dl, aria-pressed, aria-current)
  • 라이트/다크 모두 대비 4.5:1 이상 (위 표 참조)
  • prefers-reduced-motion 존중 — 켜면 이동·확대 효과가 멈춤

만들면서 정한 것

1. 감정 체크인을 뺐습니다. 기획서 ④에 있었지만 학생 개인의 심리 상태 기록입니다. 개인정보 영향평가 없이 교사 동아리 산출물로 배포할 수 없습니다.

2. ④와 ⑦을 하나로 합쳤습니다. 기획서 ④(공동체 소통·학급 회의)와 ⑦(학급 자율 의사결정 캘린더)은 안건함·투표·약속 체크가 70% 겹칩니다. 따로 만들 이유가 없습니다.

3. 중복 투표를 막지 않았습니다. 계정이 없으므로 기술적으로 막을 방법이 없습니다. 교사가 지켜보는 앞에서 기기를 돌리는 방식이라 실제로는 문제가 되지 않습니다. 계정을 넣는 순간 무기명이 깨집니다.

v0.3 — 실천 기록이 오늘에만 찍히던 것

1. 지난 날을 채울 수 있습니다 ★

v0.2의 실천 기록은 오늘 날짜에만 쓸 수 있었습니다.

if (r.log[today] === v) delete r.log[today]; else r.log[today] = v;

그래서 금요일에 한 주를 몰아 정리할 수 없었고, 하루 빠뜨리면 그 칸은 영영 비었습니다. 학급 약속은 매일 보는 것인데, 띠가 구멍투성이가 되면 아무도 보지 않습니다.

이제 14일 띠의 칸을 직접 누릅니다. 누를 때마다 기록 없음 → 잘 지켰어요 → 조금 아쉬워요 → 못 지켰어요 로 돌고, 한 바퀴 돌면 지워집니다 (잘못 찍은 것을 되돌릴 수 있어야 합니다). 칸마다 날짜가 적혀 있고 키보드로도 됩니다.

2. 색만으로 알리지 않습니다 — 원칙 4

띠가 aria-hidden="true" 에 배경색뿐이었습니다. 더 나쁜 것은 이 앱의 인쇄가 일부러 흑백이라, 종이에서는 세 값이 전부 같은 회색으로 나왔다는 점입니다.

● ◐ ○ 기호를 함께 넣었습니다. 색이 없어도, 흑백으로 뽑아도 구분됩니다.

3. 교실에 붙일 한 장

회의록만 인쇄되고, 정작 매일 보는 학급 약속은 붙일 수가 없었습니다. 약속 목록 + 14일 실천 표 + 기호 설명이 A4 한 장으로 나갑니다.

종이 아래에 「학급 전체를 기록한 것입니다. 학생 개인의 기록이 아닙니다」를 적었습니다. 교실 벽에 붙는 종이이기 때문입니다.

4. 인쇄 미리보기

printMinutes() 가 바로 window.print() 로 갔습니다. 판면 규칙을 @media print 밖으로 꺼내 미리보기와 인쇄가 같은 HTML·같은 규칙을 쓰게 했습니다.

5. 이 앱의 마크

이름 없이 넣는 상자 — 쪽지가 상자로 들어가는 모양입니다. 이 앱의 존재 이유가 무기명입니다.

손대지 않은 것 — 익명 보장은 이미 구조로 되어 있었습니다. 단계가 넘어갈 때 LEAP.shuffle() 로 순서를 섞고, 제출 시각을 기록하지 않습니다. 소규모 학급에서 제출 순서만으로 누가 썼는지 추정되는 것을 막는 장치입니다.

v0.4 — 이름을 바꾸고, 잃는 길을 막았습니다

1. 「학급 자율 의사결정 보드」 → 「학급 회의」 ★

앞의 것은 기획서의 말입니다. 기획서 ④와 ⑦을 합칠 때 두 제목을 이어 붙인 이름이라 길고, 선생님이 찾을 때 쓰는 말이 아닙니다. 도구를 고르러 온 사람이 목록에서 읽는 말은 「학급 회의」입니다. 하는 일은 그대로입니다.

검사가 옛 이름이 화면에 남아 있지 않은지 셉니다 — 남아도 되는 것은 「이렇게 바뀌었습니다」라고 적어 둔 머리 주석 하나뿐입니다.

2. 모아 보기 창 (위 「실시간은 어디까지 되는가」)

3. 되돌릴 수 없는 일을 「예 / 아니오」로 묻지 않습니다 ★ — 마스터 함정 37·38번

v0.3 의 「파일에서 가져오기」가 가장 나빴습니다.

[확인] 지금 자료에 합치기
[취소] 덮어쓰기 — 지금 자료를 지우고 가져온 것으로 바꿉니다

그만두려고 [취소]를 누르면 자료를 지우는 쪽으로 갔습니다. Esc 도 마찬가지입니다. 창을 닫는 행동이 가장 위험한 일을 고르는 자리였습니다.

이제 길을 갈라 놓고 잃지 않는 길을 맨 위에 둡니다. 그만두기는 늘 있고, Esc 와 바깥 누르기는 아무 일도 일으키지 않습니다.

4. 지우는 대신 되돌립니다 — 마스터 함정 39번

약속과 회의록은 이제 묻지 않고 지워지고, 한 걸음 되돌릴 수 있습니다. 「지울까요?」는 잘못 누르는 것을 못 막습니다 — 누르던 손이 그대로 「예」를 누릅니다. 되돌리면 원래 있던 자리로 돌아갑니다(맨 뒤에 붙이면 순서가 바뀌고, 순서가 바뀌면 되돌린 것이 아닙니다). 여러 걸음을 쌓지 않는 것은 일부러입니다.

5. 「6명 중 4명」

학급 인원을 적어 두면 모으는 동안 몇 명이 남았는지가 띠와 함께 보입니다. 안 적으면 v0.3 과 똑같이 개수만 나옵니다 — 껐다 켜는 기능이 아니라 「안 적으면 없는 것」입니다. 누가 안 냈는지는 앱도 모릅니다. 세기만 합니다. 이름을 받는 칸은 여전히 없습니다.

6. 미리보기 종이가 인쇄 종이와 폭이 달랐습니다 — 마스터 함정 31번

미리보기는 글이 놓이는 폭이 162mm 였는데 인쇄는 186mm 였습니다. 24mm 차이로 14일 실천 띠가 미리보기에서만 좁아 보였습니다. 이제 @page 와 같은 값(210mm · 14/12mm)입니다.

7. PDF 파일 이름 — 마스터 함정 27번

브라우저는 「PDF 로 저장」의 이름으로 document.title 을 씁니다. 회의록 열 장을 뽑으면 열 장이 같은 이름이었습니다. 이제 학급회의록_3학년 1반_9월 첫째 주 학급 회의_2026-09-04 꼴입니다.

8. AI 초안이 엉뚱한 회의를 가리키고 있었습니다 — 마스터 함정 28번

프롬프트를 만드는 조각이 current 를 id 로 알고 m.id === x.current 로 찾았는데, 앱 본체에서 current 는 회의 객체입니다. 늘 빗나가서 오늘 여는 회의가 아니라 가장 최근에 마친 회의의 제목이 들어갔습니다. 한 파일 안의 두 조각이 자료의 모양을 다르게 알고 있던 자리입니다.

9. 걷어낸 것

세 번째 걸음(해결책 모으기)에서 무기명 안내 넉 줄을 다시 펼치지 않습니다. 같은 넉 줄을 두 번 읽는 사람은 없고, 읽지 않는 안내는 자리만 차지하고 아래를 밀어냅니다. 한 줄로 줄이고 「아까와 같습니다」라고만 적습니다.
