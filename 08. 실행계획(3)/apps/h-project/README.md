## 왜 이 앱인가

**앱 F 는 한 차시를 짭니다. 이 앱은 여러 주에 걸친 프로젝트를 짭니다.** 단위가 다릅니다.

그리고 학교는 프로젝트를 **두 번 씁니다** — 시작 전에 「운영 계획서」, 끝난 뒤에 「운영 결과 보고서」.
따로 쓰면 같은 표를 두 번 옮겨 적게 되고, **옮겨 적는 동안 숫자가 어긋납니다.**
이 앱은 하나의 자료에 얼굴을 둘 둡니다. 계획서를 쓰고 단추 하나로 보고서가 되며,
적어 둔 것은 그대로 넘어가고 **사진과 성찰이 붙습니다.**

소규모학교와의 관계 — 프로젝트 학습은 **아이가 적을수록 오히려 잘 됩니다**(모둠이 곧 학급이고,
교사가 아이 하나하나의 탐구를 따라갈 수 있습니다). 그런데 소규모학교 교사는 겸무가 많아
**계획서를 쓸 시간이 가장 없습니다.** 이 앱이 줄이려는 것은 그 시간입니다.

## 이 앱의 얼굴 — **교과 시수 저울**

프로젝트 학습은 여러 교과에서 **시수를 빌려 옵니다.** 결재에서 실제로 걸리는 자리가 그것입니다.

```
사회 ████████ 5차시
국어 ██████   4차시
미술 ██████   4차시
창체 █████    3차시              계 16차시
```

> **계획은 18차시인데 흐름은 16차시입니다 — 2차시 모자랍니다. 어느 쪽이 맞는지 정해 주세요.**

**합계만 보고 있으면 쪼갠 값이 틀린 것은 보이지 않습니다**(마스터 함정 12번).
그래서 교과마다 막대로 그리고, 걸음 1 에 적어 둔 계획 차시와 어긋나면 그 자리에서 말합니다.

### 그래서 연계 교과를 「글」로 적게 두지 않았습니다

원본 앱은 `교과/시수` 를 **한 줄의 글**(`국어/2, 사회/1`)로 받았습니다. 그러면 **합계를 낼 수 없고,
합계를 못 내면 저울이 서지 않습니다.** 고르고 세는 칸으로 바꾸어
**합계를 낼 수 없는 상태 자체를 없앴습니다** (원칙 8번 — 잘못된 상태는 표현 불가능하게).

### 차시 번호도 앱이 셈합니다

`1~3` · `4~7` · `8~11` … 사람이 매기면 **한 줄을 지웠을 때 조용히 어긋납니다.**
소주제를 지우거나 위로 올려도 번호가 다시 셈됩니다.

## 종이

- **A4 세로.** 계획서는 Ⅰ 소개 · Ⅱ 설계(흐름·평가·예산), 보고서는 여기에 **Ⅲ 운영 결과 · Ⅳ 성찰**이 붙습니다
- 예산이 비어 있으면 **그 절이 종이에 나오지 않습니다**
- PDF 파일 이름 — `프로젝트계획서_5학년_살아 있는 역사 박물관_2026-08-07` (마스터 함정 27번)
- 긴 표는 흐르게 두고 **머리줄을 다시 그립니다** (마스터 함정 29번)

### 한글·워드로 내보내기 — 라이브러리 없이 DOCX 를 굽습니다

ZIP 은 **앱 C(스토리북)가 EPUB 을 굽는 데 쓰는 것과 같은 조각**입니다. 압축하지 않고(STORE)
담습니다 — OOXML 은 그것을 허용합니다.

**HWPX 를 만들지 않은 이유** — 원본 앱은 `.hwpx` 를 내놓지만, 그 안을 보면 `Contents/header.xml`
에 글꼴·글자·문단 속성 정의가 **하나도 없고**, 본문은 `<hp:t><![CDATA[ …HTML 통째… ]]>` 입니다.
한글이 이것을 열면 **HTML 소스가 날것으로 뜨거나 아예 열리지 않습니다.**
**열리지 않는 파일을 주는 것이 안 주는 것보다 나쁩니다.** 한글은 워드 문서를 잘 열므로
DOCX 로 냅니다. (진짜 HWPX 를 만들려면 한글로 열어 확인할 수 있어야 합니다 — 다음 과제입니다.)

**사진은 DOCX 에 담지 않습니다.** 그림 부품과 관계 파일이 더 필요하고, 여기서 실제 한글로 열어
확인할 수 없습니다. **없는 것을 있는 척하지 않습니다** — 사진은 인쇄·PDF 로 나가고,
문서에는 「사진 N장은 인쇄·PDF 로 나옵니다」라고 적힙니다.

## AI 초안 — 키 없이

| | |
|---|---|
| ① | 머리의 **「AI 초안」**이 지금까지 적은 것으로 **프롬프트를 만들어** 줍니다 |
| ② | 쓰던 챗봇(ChatGPT·Gemini·클로드) 아무 데나 붙여 넣습니다 |
| ③ | 돌아온 JSON 을 **걸음 1 의 「AI 초안 붙여넣기」**에 넣습니다 |
| ④ | **무엇이 들어오는지 먼저 보여 주고, 「이대로 받기」를 눌러야** 들어갑니다. 받은 뒤에도 **한 걸음 되돌릴 수 있습니다** |

**왜 API 키를 쓰지 않는가** — 학교에서 키 발급이 막히는 일이 잦고, 공용 컴퓨터에 키를 남기는 것도
께름칙합니다. 무엇보다 **키를 넣는 순간 이 앱은 인터넷이 필요한 앱이 됩니다**(원칙 1번).
원본 앱은 Gemini 를 직접 부르고 키를 `localStorage` 에 두었습니다. 그 둘을 걷어냈습니다.

**프롬프트에 무엇이 들어가나** — 학교·학년·주제·차시와 **고른 성취기준**입니다.
AI 에게 **그 안에서만 쓰라고** 적어 두었고, 그래도 밖의 코드를 들고 오면 **그 줄은 성취기준이
빈 채로** 들어옵니다 — 지어내서 채우지 않습니다. 그리고 그 자리를 화면이 말해 줍니다.

**학생에 대한 것은 하나도 나가지 않습니다.** 이 앱에는 학생을 적는 칸이 없고,
결과 보고서의 「아이들의 말」도 프롬프트에 넣지 않습니다.

`교육과정 편성/project-plan-app/` 의 **「프로젝트 스튜디오 AI」**(React 19 + Vite + Tailwind)를
단일 HTML 로 옮긴 것입니다. 원본은 그대로 두었습니다.

| | 원본 | 앱 H |
|---|---|---|
| 얼개 | React·Tailwind·docx·jszip·html2pdf **7개 라이브러리**, 번들 2.06MB | **단일 HTML** 206K · 외부 라이브러리 0 (원칙 1번) |
| AI | **Gemini API 직접 호출** · 키를 `localStorage` 에 저장 | **프롬프트를 만들어 줄 뿐** 앱은 아무것도 보내지 않음 (원칙 2번) |
| 성취기준 | **44건** 하드코딩 (5~6학년군 위주) | **611건** — 앱 F 와 **같은 원본에서 함께 굽습니다** |
| 연계 교과·시수 | 자유 글자 (`국어/2, 사회/1`) | **고르고 세는 칸** → 저울이 섬 |
| 차시 번호 | 사람이 적음 | **앱이 셈함** |
| 지우기 | — | **묻지 않고 하되 한 걸음 되돌리기** (함정 39·44번) |
| 파비콘 | **484KB PNG** | 인라인 SVG (브랜드 심볼) |
| 검사 | 없음 | **94개** |

### 성취기준은 두 앱이 한 원본에서 굽습니다

```bash
cd ../f-lessonplan && node bake-standards.mjs
#  ✓ 앱 F 수업 설계안 — 139K   [코드, 내용, A, B, C]
#  ✓ 앱 H 프로젝트 학습 — 34K  [코드, 내용]
```

같은 자료를 앱마다 사본으로 들고 있으면 한 곳만 고쳤을 때 나머지가 조용히 낡습니다
(마스터 함정 13번). `bake-coords.mjs` 가 A·C·E·대시보드 넷을 한꺼번에 고치는 것과 같은 방식입니다.

**담는 것은 서로 다릅니다.** 앱 F 는 성취수준 A·B·C 까지 굽습니다 — 거기서는 그 셋이 그대로
심화·기본·기초 피드백이 됩니다. 프로젝트 계획서의 평가 계획은 A·B·C 를 적는 자리가 아니므로,
**쓰지 않을 105K 를 들고 다니지 않습니다.** 검사가 「한 줄이 둘뿐인지」를 셉니다.
