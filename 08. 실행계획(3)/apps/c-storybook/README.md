## v0.3~v0.4 에서 고친 것

### 1. 표지가 인쇄되지 않던 문제

원인은 **브라우저가 CSS 배경을 기본으로 인쇄하지 않기** 때문이었습니다. 표지 바탕이 `background: linear-gradient(...)` 였는데 그게 안 찍히고, 글자는 흰색이라 **흰 종이에 흰 글씨**가 나왔습니다.

고친 방법은 배경을 **인라인 SVG(전경 요소)로 그리는 것**입니다. `<svg><rect fill="url(#gradient)"/></svg>` 는 그림이므로 「배경 그래픽」 설정과 무관하게 항상 인쇄됩니다. 사진 위의 어두운 띠도 같은 방식으로 바꿨습니다.

```
before  .PC.grad { background: linear-gradient(...) }   ← 인쇄 안 됨
after   <svg class="cbg"><rect fill="url(#..)"/></svg>  ← 항상 인쇄됨
```

보조로 `print-color-adjust: exact` 도 넣었고, 쪽 높이를 A4 실제 인쇄 영역(271mm)에 맞췄습니다.

### 2. EPUB 내보내기

외부 라이브러리 없이 **ZIP 작성기를 직접 만들었습니다** (CRC32 + 로컬 헤더 + 중앙 디렉터리). 압축하지 않고(STORE) 담습니다. 사진은 이미 JPEG 로 압축돼 있고, EPUB 규격상 `mimetype` 은 첫 항목이면서 무압축이어야 하기 때문입니다.

EPUB 3 구조를 갖춥니다 — `container.xml`, `content.opf`(매니페스트·스파인·메타데이터), `nav.xhtml`(차례), 쪽마다 XHTML, `style.css`, 이미지.

**EPUB 은 XHTML(엄격한 XML)이라 태그 하나만 안 닫혀도 열리지 않습니다.** 그래서 `node test-epub.js` 가 실제로 파일을 만들어 `unzip -t` 로 무결성을 보고, 풀어서 모든 XML 의 적합성과 매니페스트 일관성까지 확인합니다.

종이책(인쇄)은 A4 고정 배치, EPUB 은 글자 크기를 바꿀 수 있는 흐름 배치입니다. 그래서 EPUB 에서는 사진 크기·확대 설정이 적용되지 않고 사진이 폭에 맞게 들어갑니다.

### 3. 페이지 편집

**한 장씩** 과 **모아 보기** 두 방식으로 나눴습니다.

| 방식 | 쓰임 |
|---|---|
| **한 장씩** | 왼쪽에 실제 인쇄 모습, 오른쪽에 조작. 아래 축소판 띠로 아무 쪽이나 바로 이동 |
| **모아 보기** | 전체를 격자로 놓고 순서 바꾸기·지우기 |

**사진 크기 조절**이 들어갔습니다. 이전에는 배치만 고를 수 있었습니다.

| 조절 | 범위 | 하는 일 |
|---|---|---|
| 사진 크기 | 25~85% | 쪽에서 사진이 차지하는 높이 |
| 사진 확대 | 100~260% | 사진을 키워 원하는 부분만 보이게 |
| 좌우 위치 | 0~100% | 잘릴 때 어느 쪽을 남길지 |
| 위아래 위치 | 0~100% | 〃 |

「사진 가득」 배치에서는 크기 슬라이더가 숨습니다. 이미 전면이라 조절할 것이 없습니다.

글을 칠 때 화면을 다시 그리지 않고 **미리보기만 갱신**합니다. 그러지 않으면 타이핑 중 커서가 튑니다.

### 4. 표지 미리보기

표지 탭도 왼쪽 미리보기 + 오른쪽 입력으로 바꿨습니다. 적는 대로 표지가 바로 바뀝니다.

### 5. 모으기 — 학생 작업물 합치기

**설계상 가장 어려웠던 부분입니다.**

문제는 저장 공간입니다. 학생 6명 × 8쪽 × 250KB = **12MB**, 브라우저 한도는 **5MB**. 합본을 저장하려는 순간 터집니다.

그래서 **합본은 「저장하는 문서」가 아니라 「바로 내보내는 결과물」로** 다룹니다.

```
① 학생마다 자기 기기에서 책을 만들고 「파일로 내보내기」
② 선생님이 그 파일들을 모읍니다 (USB · 메신저 · 학급 클라우드 무엇이든)
③ 「모으기」에서 여러 개를 한꺼번에 고르면 한 권으로 합쳐집니다
④ 합본은 메모리에만 있습니다 → 바로 인쇄 · EPUB · 파일로 내보내기
```

화면에 **"합본은 저장되지 않습니다. 새로 고치면 사라집니다"** 를 명시했습니다.

- **모둠마다 속표지**를 자동으로 넣습니다 (끌 수 있음)
- 순서를 바꾸면 문집 차례가 바뀝니다
- 쪽 아이디를 새로 매깁니다. 학생마다 아이디가 겹치면 뒤에서 덮어써집니다
- **사진 한 번 더 줄이기** (1200px · 75%) 를 켜면 문집 파일이 작아집니다. 한 장씩 넘기며 처리하고 진행률을 보여 줍니다

**왜 서버를 안 쓰는가**: 서버·계정을 넣으면 4주 안에 못 끝내고, 학생 사진이 외부로 나가 개인정보 문제가 생기며, 보안성 검토도 무거워집니다. 파일로 주고받는 방식은 교사가 무엇이 오가는지 눈으로 볼 수 있습니다.

### 6. 마지막 장 꾸미기 (v0.4)

책의 맨 뒤는 **판권지(colophon)** 자리입니다. 그동안 고정된 문구만 찍혔는데, 이제 꾸밀 수 있습니다.

| 넣는 것 | 설명 |
|---|---|
| 맺음말 제목 | 예: 「우리가 배운 것」 |
| 맺음말 | 탐방을 마치고 든 생각 |
| 만든 사람 | 모둠 이름 권장 |
| 학교·학급 | 예: 안동초등학교 3학년 1반 |
| 지도 교사 | |
| 모양 | 흰 바탕 / 색으로 / 단색 / 사진으로 |

**책 제목·날짜·저작권은 자동으로 들어갑니다.** 지울 수 없습니다.

표지와 같은 편집 방식입니다 — 왼쪽 미리보기, 오른쪽 입력. 「사진으로」를 고를 때만 사진 칸이 나타납니다. 쓰이지 않는 사진을 넣게 두면 저장 공간만 먹기 때문입니다.

인쇄와 EPUB 양쪽에 들어갑니다. EPUB 에서는 `epub:type="colophon"` 으로 표시해 뷰어가 판권지로 인식합니다.

**예전에 저장한 책에는 이 항목이 없습니다.** `backOf()` 가 없으면 기본값으로 채워 돌려주므로 열 때 터지지 않습니다. 이 경우도 테스트로 고정해 두었습니다.

합본(문집)에도 마지막 장이 붙고, 참여한 모둠 이름이 「만든 사람」에 자동으로 들어갑니다.

## v0.5 — 「지역 탐방」을 진짜로 넣었습니다

v0.4까지 이 앱은 솔직히 **사진 넣는 책 만들기**였습니다. 이름에 「지역 탐방」이 붙어 있을 뿐,
경상북도도 없고 어디를 다녀왔는지도 남지 않았습니다. 사진첩과 다를 게 없었습니다.

v0.5의 전환은 한 문장입니다.

> **쪽마다 「어디인지」가 붙고, 그것이 모여 지도 한 장이 된다.**

책을 덮고 나면 남는 것이 사진이 아니라 **우리가 어디를 다녀왔는가** 가 됩니다.

### 경상북도 22개 시군이 들어 있습니다

**군위군은 없습니다.** 2023년 7월 1일 대구광역시로 넘어갔습니다.
경북 교육 자료에 군위를 경북으로 두면 그것부터 틀립니다. 검사가 이걸 고정합니다.

시 10곳 · 군 12곳. 시군마다 위경도와 대표 탐방지 3~5곳이 들어 있습니다.

### 지도는 직접 그렸습니다

지도 API를 쓸 수 없습니다 — 이 앱은 인터넷 없이 도는 것이 원칙입니다.
그래서 **실제 위경도를 화면 좌표로 옮겨** SVG로 그립니다. 시군끼리의 **상대적 위치는 실제와 같습니다.**

| 그린 것 | 왜 |
|---|---|
| 시군 22곳의 점 | 위경도를 그대로 투영 — 위치가 맞습니다 |
| **동해안선** | 이것 하나로 「경북」으로 읽힙니다. 오른쪽이 바다라는 것만 알면 방향이 잡힙니다 |
| 울릉군 딸린 상자 | 경도 130.9도. 같이 그리면 육지가 납작해집니다 |

**경계선 전체는 그리지 않았습니다.** 손으로 그리면 반드시 틀리고, 경북 선생님은 그 모양을 압니다.
사실이 분명한 것(해안선·바다)만 그리고, 화면에도 "실제 위치를 옮겨 그린 것"이라고 적었습니다.

### 초성으로 찾습니다

아이들이 쓰는 법에 맞췄습니다.

```
ㅂㄱㅅ  →  불국사
ㄱㅈ    →  경주 · 김천
주왕산  →  청송군
```

### 쪽마다 「여기는 어디?」

쪽 편집기 맨 위에 있습니다. 사진과 글보다 **먼저** 묻습니다.
시군을 고르면 그 시군의 탐방지 목록이 나오고, 없으면 직접 적습니다.

### 탐방 지도 쪽 — 이 앱의 얼굴

다녀온 곳이 지도에 찍히고 **순서대로 점선으로 이어집니다.** 「우리가 간 길」입니다.
표지 다음에 들어가고, **인쇄물과 EPUB에도 그대로** 갑니다.

EPUB에서는 SVG를 XHTML 안에 그대로 넣습니다. 그림 파일이 아니라 글자로 된 그림이라
용량이 거의 들지 않고 확대해도 깨지지 않습니다. 대신 태그 하나만 안 닫혀도 책이 안 열리므로,
`test-epub.js`가 지도 쪽이 든 책을 실제로 만들어 XML 적합성까지 확인합니다.

### 도장 모으기

22개 시군 중 몇 곳을 다녀왔는지 셉니다.
작은 학교들이 서로 다른 지역을 맡아 「모으기」로 합치면 경상북도가 채워집니다.

### 우리 학교에서 얼마나 먼가

학교가 있는 시군을 정하면 탐방지까지의 거리가 나옵니다.
**직선거리입니다.** 안동–경주가 91km로 나오는데 도로로는 120km쯤입니다.
화면에 「직선 91km」라고 적어 견학 계획을 잘못 세우지 않게 했습니다.

### 탐방지는 고쳐 쓰라고 넣은 것입니다

기본 목록은 **출발점일 뿐입니다.** 학교가 실제로 가는 곳은 유명한 명소가 아닌 경우가 많습니다.
마을 앞 개울, 오래된 나무, 시장 골목 — 「탐방지 더하기」로 얼마든지 넣습니다.

> **배포 전에 확인이 필요합니다.** 기본 탐방지 목록은 널리 알려진 곳으로 채웠지만,
> 경북 선생님이 한 번 훑어 주시는 편이 안전합니다. 틀린 곳이 있으면 목록만 고치면 됩니다.

## v0.6 — 저장 공간 · 우리 학교 · 표지

### 1. 4.2MB 벽을 없앴습니다 — 「책장」

예전에는 **한 번에 한 권**이었습니다. localStorage 가 5MB 언저리에서 막히기 때문입니다. 사진 스무 장이면 찼고, 합본은 아예 저장할 수 없었습니다.

같은 **「이 기기 안」**을 지키면서 넓힐 방법이 있습니다. **IndexedDB** 입니다.

| | 예전 (localStorage) | 지금 (IndexedDB) |
|---|---|---|
| 담기는 양 | 4.2MB | 브라우저가 내주는 몫 — 크롬에서 **수십~수백 GB** |
| 둘 수 있는 책 | 한 권 | 몇 권이든 |
| 합본 저장 | 안 됨 | 됨 (「책장에 넣기」) |
| 인터넷 | 안 씀 | **여전히 안 씀** |

넓어진 것은 저장소지 원칙이 아닙니다. 나가는 요청은 여전히 하나도 없습니다.

**못 쓰는 브라우저도 있습니다.** 그때는 예전처럼 한 권 · 4.2MB 로 물러나고, **왜 그런지 화면에 적습니다.** 조용히 못 하고 넘어가면 사파리에서 연 선생님은 이유를 알 수 없습니다.

예전에 만들던 책은 처음 열 때 **책장으로 옮겨 옵니다.** v0.5 까지 쓰던 사람의 책이 사라지면 안 됩니다.

> 책장은 **이 브라우저 안**에 있습니다. 기록을 지우거나 다른 컴퓨터로 옮기면 따라오지 않습니다. 그래서 화면에도 「그래도 파일로 내보내 두세요」를 남겼습니다.

### 2. 우리 학교를 이름으로 찾습니다

예전에는 「우리 학교가 있는 곳」이 **시군 고르기**였습니다. 안동시를 고르면 안동시 한가운데에 점이 찍혔습니다. 임하면에 있는 학교나 풍천면에 있는 학교나 같은 자리였습니다.

이제 **경상북도의 학교 917곳**이 **위도·경도까지** 앱 안에 들어 있습니다.

| | |
|---|---|
| 이름·학교급·주소 | 교육부 「학교기본정보」 (교육정보 개방 포털 `open.neis.go.kr`) |
| **위도·경도** | 교육부 **학교알리미** (`schoolinfo.go.kr`) — `LTTUD` · `LGTUD` |
| 범위 | 경상북도교육청(R10) 초 474 · 중 260 · 고 183 = **917교** |
| 좌표가 있는 곳 | **916교** |
| 이용조건 | 공공누리 제1유형 (출처표시) |
| 받은 때 | 2026년 8월 |

두 곳을 쓴 이유는 하나입니다. **개방 포털에는 좌표가 없고, 학교알리미에는 좌표가 있습니다.** 인증키도 따로입니다 — 생김새가 똑같아 헷갈립니다(`open api/README.md` 참고).

**분교장 18곳도 그대로 들어 있습니다.** 작은 학교를 위한 앱이 분교장을 빠뜨리면 앞뒤가 맞지 않습니다.

이름 · 초성 · 주소로 찾습니다. `ㅇㄷㅊ` 만 쳐도 안동초등학교가 나옵니다. 고르면 시군이 저절로 정해지고, 마지막 장의 「학교·학급」에도 한 번에 넣을 수 있습니다.

**목록에 없으면** 「목록에 우리 학교가 없어요」를 열어 시군만 골라도 됩니다. 예전처럼 동작합니다.

#### 「시군」과 「학교」는 다릅니다

안동시 길안초등학교로 해 보면 차이가 보입니다.

길안면은 안동 시내가 아니라 청송 쪽에 붙어 있습니다. 절반입니다.
현장학습 계획을 세울 때 답이 그대로 달라지는 자리입니다.

### 3. 표지를 셋으로 나눴습니다

예전에는 「색으로 · 사진으로 · 단정하게」 셋뿐이었습니다. 한 반 스무 권이 모두 같은 표지가 되었습니다.

| 고르는 것 | 가짓수 |
|---|---|
| **바탕** | 10 — 새벽 · 동해 · 숲 · 노을 · 밤하늘 · 황토 · 자주 · 단정하게 · 한지 · 흰 종이 |
| **무늬** | 6 — 없음 · 물결 · 산 · 점 · 격자 · 햇살 |
| **글자 자리** | 3 — 아래 · 가운데 · 위 |

180가지가 되지만 **고르는 일은 여전히 셋**입니다.

- 한지 · 흰 종이처럼 **밝은 바탕에서는 글자와 상표가 저절로 어두워집니다.** 흰 종이에 흰 글자가 나오면 아무것도 안 보입니다.
- 무늬는 CSS 배경이 아니라 **SVG** 입니다. 브라우저에서 「배경 그래픽 인쇄」를 꺼 놓아도 인쇄됩니다.
- **마지막 장이 표지 바탕을 따라갑니다.** 앞뒤가 따로 노는 책은 만들다 만 것처럼 보입니다.
- 사진을 넣으면 그 사진이 표지가 됩니다. 「바탕으로」를 눌러 되돌릴 수 있습니다.

예전에 만든 책은 그대로 보입니다. `grad` 는 「새벽」, `solid` 는 「단정하게」로 읽습니다.

## v0.8 — 학생이 쓰는 앱답게 (2026. 8. 7.)

### ★ 같은 단추가 두 가지 다른 일을 하고 있었습니다

```js
function startNewBook() {
  if (V.mode !== 'idb') { db.reset(); ... }   // 지금 책이 지워집니다
  vaultAdd(newRec(), ...);                    // 책이 한 권 늘어납니다
}
```

책장이 열리면(IndexedDB) 책이 한 권 늘고, 안 열리면 **지금 책이 지워집니다.**
사파리 사생활 보호 창처럼 넓은 저장소가 안 열리는 자리가 실제로 있고,
쓰는 사람은 자기가 어느 쪽인지 모릅니다. 「새 책 만들기」를 눌렀는데 한 시간 동안
쓴 책이 사라질 수 있었습니다.

이제 **모드마다 다른 것을 묻습니다.** 지울 수밖에 없는 자리에서는
**먼저 파일로 내보내는 길을 맨 위에** 둡니다. 책장이 열리는 자리에서는 아무것도
묻지 않습니다 — 잃을 것이 없으니까요.

### 1. 탭 일곱 개에 순서가 없었습니다

`표지 · 탐방지 · 페이지 · 마지막 장 · 미리보기 · 책장 · 모으기`

앞의 넷은 **만드는 차례**이고 뒤의 셋은 성격이 다릅니다(보기 / 보관 / 선생님).
그것이 화면에 드러나지 않아, 처음 여는 학생은 어디부터인지 알 수 없었습니다.

```
① 표지  ② 탐방지  ③ 페이지  ④ 마지막 장 │ 미리보기  책장 │ 학급 문집〔선생님〕
```

걸음마다 아래에 **「다음 걸음으로」** 줄이 붙습니다. 마지막 걸음은 미리보기로 보냅니다.
번호는 `aria-hidden` 이라 읽어 주는 프로그램이 「1 표지」로 두 번 읽지 않습니다.

### 2. 빈 책에서 시작했습니다 — 「뼈대 책」

3학년이 「책 제목」 빈칸을 마주합니다. 그런데 이 앱은 **콘텐츠를 주지 않기로** 정해 둔
앱입니다 — 기획서에서 「지역 역사 콘텐츠 DB」를 뺀 이유가 그것입니다:
**콘텐츠는 학생이 채우는 것.**

그래서 완성된 책이 아니라 **뼈대만** 놓습니다.

```
1. 가는 길에 무엇을 보았나요?
2. 가장 기억에 남는 것은 무엇인가요? 왜 그런가요?
3. 처음 알게 된 것 한 가지를 적어 보세요.
4. 친구에게 이곳을 소개한다면 뭐라고 말할까요?
```

**글은 한 줄도 채우지 않습니다.** 물음은 안내(placeholder)로만 보여 주므로
학생이 지울 것이 없습니다. 자리와 물음만 있고, 채우는 것은 학생입니다.

### 3. 「모으기」가 무엇인지 열기 전엔 몰랐습니다

이름을 **「학급 문집 만들기」**로 바꾸고, 탭에 **〔선생님〕** 딱지를 붙였습니다.
화면 첫 줄에서도 「선생님이 쓰는 화면입니다」라고 말합니다.
학생에게는 **「파일로 내보내기」까지가 자기 일**이라고 적어 두었습니다.

### 4. 사진 용량을 넣고 나서야 알았습니다

용량 막대는 **책장 화면 아래**에 있었습니다. 사진을 다 넣고 나서 보게 되고,
그때는 「가득 찼습니다」를 만난 뒤입니다.

이제 **「페이지」 화면에서** 말합니다 — 이 사진이 얼마고, 지금 책이 얼마고,
앞으로 몇 장쯤 더 들어가는지. 넣어 본 사진이 없으면 **어림하지 않습니다**
(지어낸 수를 보이지 않기 위해서입니다).

### 5. 지운 것을 되살릴 길이 없었습니다

학생이 쓰는 앱인데요. 사진 한 장에 이십 분씩 걸린 쪽을 잘못 눌러 지우면 그대로 끝이었습니다.

**확인창을 없애고 되돌릴 수 있게** 했습니다. 「이 쪽을 지울까요?」는 잘못 누르는 것을
못 막습니다 — 누르던 손이 그대로 「예」를 누릅니다. 대신 바로 지우고 화면 아래에
**되돌릴 수 있는 자리**를 12초 띄웁니다.

한 걸음만 기억합니다. 여러 걸음을 쌓으면 지운 사진이 메모리에 계속 남습니다.

### 6. 인쇄가 A4 한 종류였습니다

학급 문집 스무 권이면 종이가 수백 장입니다.

| | |
|---|---|
| **한 쪽씩** | A4 한 장에 한 쪽. 그대로 읽기 좋습니다 |
| **두 쪽씩** | A4 **가로** 한 장에 두 쪽. 반으로 접으면 책이 되고 종이가 절반입니다 |
| **양면으로** | 한 쪽씩 뽑되 인쇄 창에서 양면을 켜라고 알려 줍니다 |

`@page` 는 클래스로 못 바꾸므로 `<style id="page-size">` 를 갈아 끼웁니다.
두 쪽씩은 상자 크기를 mm 로 다시 적지 않고 **`zoom` 으로 줄입니다** — 상자 안의 글과
사진이 상자 너비에 맞춰 그려지므로(`--sc`), 상자만 줄이면 안엣것이 함께 줄어듭니다.
폭이 아니라 **높이**가 좁으니 높이를 기준으로 잡습니다(271mm → 194mm, 0.715).

> **이름이 겹쳤습니다.** 처음에 `data-lay` 를 썼는데 그것은 **쪽 배치**(사진 위/글 위)가
> 이미 쓰는 이름이었습니다. `data-paper` 로 갈랐습니다.
> 같은 이름을 두 뜻으로 쓰면 언젠가 한쪽이 다른 쪽을 지웁니다.

### 7. AI 초안 도우미를 걷어냈습니다 ★

일곱 앱 가운데 **이것만 학생이 직접 쓰는 앱**입니다. 아이의 글을 AI 에게 맡길 자리가
아니고, 교실에서 아이 손에 AI 단추를 쥐여 주는 것도 지금 단계에서 할 일이 아닙니다.

머리 단추·모달·조각(스크립트와 CSS)을 통째로 뺐습니다. 그 자리를 **뼈대 책**이 대신합니다 —
AI 가 글을 써 주는 대신, **물음을 놓고 학생이 답하게** 합니다.

메인 페이지의 공통 검사도 「일곱 앱 모두에 AI 초안 도우미가 있는가」에서
**「교사가 쓰는 앱에만」**으로 바꿨습니다. 앱 C 에 다시 붙으면 그 검사가 잡습니다.

## v0.7 — 미리보기가 거짓말을 하고 있었습니다

「인쇄하면 이 모양 그대로 나옵니다」라고 적어 두었는데, **그대로 나오지 않았습니다.**

원인은 종이를 그리는 코드가 **두 벌**이었다는 것입니다.

| | 미리보기 | 인쇄 |
|---|---|---|
| 상자 | `.sheet` — 비율 1 : 1.414 | `.P` — 186 × 271mm (1 : 1.457) |
| 좌우 여백 | 24px / 520px = **4.6%** | 3mm / 186mm = **1.6%** |
| 글자 | `.875rem` | `11pt` |
| 본문 글꼴 | 명조 | **지정 없음(고딕)** |

비슷해 보이도록 값을 손으로 맞춰 놓았을 뿐입니다. 그래서 **글이 줄바꿈되는 자리가 달랐습니다.**
게다가 `.tx` 에 `overflow:hidden` 이 걸려 있어, 넘친 글은 **아무 말 없이 사라졌습니다.**
스무 권을 뽑고 나서야 압니다.

### 1. 상자를 하나로 만들었습니다

A4 에서 여백을 뺀 **실제 크기 186 × 271mm** 로 짜고, 화면에서는 `transform: scale()` 로 **줄이기만** 합니다.
줄이기는 배치를 바꾸지 않으므로, 미리보기에서 넘치는 자리와 종이에서 넘치는 자리가 **같습니다.**

```
before  .sheet(px·rem)  ┐              → 화면
        .P(mm·pt)       ┘ 두 벌을 손으로 맞춤 → 종이

after   .sheet(186×271mm) ─┬─ scale(0.74) → 화면
                           └─ scale(1)    → 종이
```

인쇄용 그리기 함수(`printHTML` · `printMapPage`)도 없앴습니다. 이제 인쇄는 미리보기와 **같은 함수**를 부릅니다.
`printHTML(b)` 는 `bookHTML(b, true)` 한 줄입니다. 갈릴 수가 없고, 검사가 **글자 하나까지 같은지** 봅니다.

덤으로 축소판(`.mini`)에 따로 글자 크기를 정해 줄 일도 없어졌습니다. 진짜 축소판입니다 — 15줄쯤 지웠습니다.

### 2. 잘리는 쪽을 뽑기 전에 알려 줍니다

상자가 실제 크기라서, **화면에서 넘치면 종이에서도 넘칩니다.** 그걸 재서 표시합니다.

- 미리보기에서 그 쪽에 **주황 테두리와 「글이 잘립니다」 딱지**
- 한 장씩 편집 화면에서 **무엇을 어떻게 하면 되는지** 한 줄
- 「뽑기 전에 한 번」 칸에 **몇 쪽이 잘리는지**

### 3. 뽑기 전에 한 번 — 인쇄 전 점검

미리보기 맨 위에 붙습니다. 스무 권을 뽑기 전에 보라고 만든 것입니다.

| 짚는 것 | 왜 |
|---|---|
| 사진도 글도 없는 쪽 | 빈 종이가 나갑니다 |
| 사진에 설명이 없는 쪽 | 눈이 불편한 친구가 이 쪽을 들을 수 없습니다 |
| 어디인지 적지 않은 쪽 | 탐방 지도에 찍히지 않습니다 |
| 글이 잘리는 쪽 | 뒤가 사라집니다 |

**아쉬운 데가 없으면 「그대로 뽑으셔도 됩니다」라고 말합니다.** 늘 잔소리하면 아무도 읽지 않습니다.

### 4. 사진 여러 장을 한 번에 — 쪽이 저절로 만들어집니다

견학에서 돌아온 아이의 사진은 열 장이 넘습니다. 예전에는 「쪽 더하기 → 사진 고르기」를 **열 번** 되풀이해야 했습니다.

이제 **「사진 여러 장 넣기」** 하나로 끝납니다. **사진 한 장이 한 쪽**이 되고, 글은 그다음에 앉아서 적습니다.
사진 순서가 곧 책의 뼈대입니다.

- **한 장씩** 줄여 넣습니다. 열 장을 한꺼번에 캔버스에 올리면 낡은 태블릿이 멈춥니다.
- 진행 상황을 소리로 읽어 줍니다 — `사진 3 / 12장 넣는 중입니다`
- 한 장이 깨져도 **나머지가 이어집니다.** 예전에는 그 자리에서 멈춰 버렸습니다.
- 저장 공간이 차면 **거기서 멈추고** 말합니다. 계속 넣어 봐야 다 실패합니다.

### 5. 이 앱의 마크

**펼친 책 위를 가로지르는 점선 길**입니다. 이 앱이 사진첩과 갈리는 자리가 「어디를 다녀왔는가」이고,
그것이 책이 됩니다. 길이 책등을 넘어가는 것은 일부러입니다 — 하루의 길은 여러 쪽에 걸쳐 이어집니다.

**판권지와 표지의 TEAM LEAP 상표는 그대로입니다.** 저작권 표기는 지우지도 바꾸지도 않습니다.

## 개인정보

**이 앱은 사진을 다룹니다. 학생 얼굴이 들어갈 수 있습니다.**

- 사진과 글은 모두 **이 기기 안에만** 있습니다. 서버로 보내지 않습니다.
- 파일로 내보내면 **사진도 함께 담깁니다.** 누구에게 보낼지 교사가 먼저 확인해야 합니다.
- 학생 실명 대신 **모둠 이름**을 쓰도록 안내합니다.
- 얼굴이 담긴 사진을 학교 밖으로 내보낼 때는 보호자 동의가 필요합니다.

## 접근성

- **사진 설명(대체 텍스트)을 학생이 직접 적게 합니다.** "눈이 불편한 친구가 소리로 듣습니다"라고 설명을 붙였습니다. 접근성을 지키는 동시에 가르칩니다. EPUB 의 `alt` 로도 그대로 들어갑니다.
- 색만으로 정보를 전달하지 않음
- 전체 키보드 조작 가능. 사진 고르는 자리도 `Enter`/`Space` 로 열림
- 포커스 표시 3px, 버튼 최소 높이 46px
- 사진 넣기·저장 결과를 `role="status"` 로 읽어 줌
- 라이트/다크 모두 대비 4.5:1 이상
- `prefers-reduced-motion` 존중

※ 자동 검사 도구(K-WAH 등) 정식 진단은 11월 과제입니다.

## 파일

```
c-storybook/
├─ index.html      ← 전부 여기에 (HTML + CSS + JS)
├─ test.js         ← node test.js       화면·편집·탐방·책장·학교·표지·종이 270개
├─ test-epub.js    ← node test-epub.js  EPUB 파일 자체 42개
├─ verify-epub.py  ← test-epub.js 가 불러 쓰는 규격 검사
└─ README.md
```

`kit/leap.css` 와 `kit/leap.js` 가 원본이고, `index.html` 안의 것은 **사본**입니다. 원본을 고치면 앱 안의 블록도 함께 고쳐야 합니다.

`index.html` 맨 아래 `window.__LEAP_TEST__` 훅은 **점검용**입니다. `test.js` 가 미리 만들어 둘 때만 붙고, 브라우저에서는 아무 일도 하지 않습니다.
