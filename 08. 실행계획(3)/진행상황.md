## 〔2026. 8. 6.〕 앱 G v0.4 — 그림이 거짓말을 하던 자리

현장에서 **한 반 자료를 실제로 넣어 보고** 나온 것입니다. 넷 다 화면이 없는 것을
그리고 있었습니다. 자세한 것은 `apps/g-classdata/README.md`, 재발 방지는
마스터 7장 함정 15~20번.

### 여기서 나온 원칙 하나

> **만점으로 나눠 0~1 로 만들었다는 것은 「그릴 수 있다」는 뜻이지
> 「더해도 된다」는 뜻이 아닙니다.**

단원평가(100점 만점)와 수행평가(상·중·하)를 「성취」 한 선으로 이었더니
**31% → 100%, 「+69%p 올랐습니다」** 가 나왔습니다. 반 전체가 「상」이면 그
항목의 평균은 100% 이고, 그것이 100점 만점의 만점과 같은 자리에 찍힙니다.
**오른 것은 아이가 아니라 자였습니다.** 다른 앱에도 그대로 적용되는 이야기입니다.

### 결정 넷

| 결정 | 왜 |
|---|---|
| 계열을 **범주 × 척도**로 가른다 | 위 원칙. 자가 다르면 선을 따로 긋고, 왜 따로인지 화면이 말한다 |
| **한 회차 = 하루** | 정서 6문항을 하루에 물으면 항목은 여섯이지만 회차는 하나다. v0.3 은 여섯으로 세어 하루 안에서 「−5%p 내림」을 만들어 냈다 |
| 산점도 축을 **고르게** 한다 | 말없이 「나중 항목」을 고르면 전원 「상」인 항목이 걸려 스물넷이 한 점에 겹친다. 겹친 점은 **묶어 인원을 적는다** — 흔들어 흩뜨리면(jitter) 없는 자리를 만드는 것이다 |
| 정서 기본을 **역량 이름 여섯**으로 | 여기 들어오는 정서 값은 설문지 원본이 아니라 **관찰·감정 진단·일기에서 이미 한 번 정리한 값**이다. 열 이름이 설문 문장이면 정리한 것을 또 쪼개야 한다. 7문항은 「설문 7문항 그대로 쓰기」로 남겼다 |

### 뒤집은 결정 하나

**「엑셀 서식은 넣지 않는다」(v0.3)를 뒤집었습니다.** 근거였던 「구글시트에서
깨진다」는 **조건부 서식·수식·표 스타일**에만 해당하고, **채우기 색·굵게·
테두리·틀 고정은 구글시트가 그대로 받습니다.** 그 넷만 씁니다.

받은 사람이 파일을 열고 가장 먼저 하는 질문은 **「어디에 적나」**입니다.
흰 표 한 장을 주고 안내 시트를 읽으라는 것은 답이 아니었습니다.
노랑=적는 곳 · 파랑=항목 정하는 곳 · 초록=번호·이름 · 회색=고치지 말 것.
**서식이 값을 바꾸지 않는다는 것은 왕복 검사가 고정합니다.**

곁들여, 「보기」 시트의 예시 이름을 **성을 뗀 순우리말**(가온·나래·다솜·라온·
미르·바다)로 바꿨습니다. 흔한 성+이름은 **실제로 그 이름의 아이가 교실에 있을
확률이 높습니다** — 받은 선생님이 자기 반 아이 이름을 예시에서 보게 됩니다.

검사 **262 → 312개**.

## 〔2026. 8. 7.〕 공통 규칙이 하나 바뀌었습니다 — AI 초안 도우미

**이 절이 오늘 가장 중요한 기록입니다.** 나머지는 앱별 개선이지만, 이것은
**일곱 앱에 걸린 규칙**이 바뀐 것입니다.

### 무엇이 바뀌었나

지금까지 「AI 초안 도우미는 **일곱 앱 모두**에 있다」가 규칙이었고, 메인 페이지 검사가
그것을 지켰습니다. 이제 **「교사가 쓰는 앱에만」**입니다.

**앱 C(지역 탐방 디지털 스토리북)에서 걷어냈습니다.** 머리 단추·모달·조각(JS와 CSS)을
통째로 뺐습니다.

### 왜

일곱 앱 가운데 **앱 C 만 학생이 직접 손대는 앱**입니다. 나머지 여섯은 교사가 씁니다.

- 아이가 쓴 글을 AI 에게 고쳐 달라고 하는 순간 **아이의 책이 아니게 됩니다.**
  (이 걱정은 원래도 있었습니다 — 그래서 v0.7 까지도 프롬프트에 아이 글을 넣지 않았습니다.
   그런데 **단추가 거기 있다는 것 자체가** 아이에게는 권유입니다.)
- 교실에서 아이 손에 AI 단추를 쥐여 주는 것은 **지금 단계에서 우리가 결정할 일이 아닙니다.**
  생성형 AI 의 학생 이용에는 나이·동의·지도 감독이 걸립니다.
- 이 앱의 기획 원칙과도 맞습니다 — 「지역 역사 콘텐츠 DB」를 뺀 이유가
  **「콘텐츠는 학생이 채우는 것」**이었습니다. AI 초안도 같은 성질입니다.

### 대신 무엇을 두었나

**뼈대 책**입니다. AI 가 글을 써 주는 대신 **물음을 놓고 학생이 답하게** 합니다.

```
1. 가는 길에 무엇을 보았나요?
2. 가장 기억에 남는 것은 무엇인가요? 왜 그런가요?
3. 처음 알게 된 것 한 가지를 적어 보세요.
4. 친구에게 이곳을 소개한다면 뭐라고 말할까요?
```

**글은 한 줄도 채우지 않습니다.** 물음은 안내(placeholder)로만 보이므로 학생이 지울 것이
없습니다. 검사가 이것을 지킵니다 — 나중에 누가 예시 글을 채워 넣으면 걸립니다.

### 새 앱을 만들 때

**「학생이 직접 쓰는 앱인가」를 먼저 정하세요.** 그렇다면 AI 초안 도우미를 넣지 않습니다.
메인 페이지 검사(`1. 깃허브 탑재 (배포)/test.js`)의 `aiApps` 목록에서 빼고,
왜 뺐는지 그 자리에 적어 두면 됩니다.

## 〔2026. 8. 7.〕 「처음으로」가 무엇의 처음인가

앱 D 를 쓰던 분이 짚어 주셨습니다. 짜던 수업을 접고 **새로 짜려면** 어디를 눌러야 하는지
알 수 없었고, 사람들은 머리의 **「처음으로」**를 눌렀습니다.

- **일곱 앱 모두** 머리 단추를 **「메인으로」**로 바꿨습니다
- **나가도 잃는 것이 없다**고 함께 알립니다 — 그것이 망설이는 진짜 이유입니다
- 앱 D 의 되감기는 「처음 구간으로」

메인 페이지 검사가 일곱 앱 + 대시보드에서 이것을 지킵니다.

**무엇을 셈해 줄지를 교사가 직접 켭니다.**

**AI 가 준 답을 그대로 붙여 넣습니다.** v0.4 까지는 프롬프트를 만들어 주고 거기서

그대로 남겨 둔 셈이었습니다.

> **창구의 규칙이 바뀌었습니다.** `window.LEAP_E` 는 원래 **셈한 결과만** 내주고 고치는

> `setDoc` 하나뿐**이고, 그 문으로 들어간 것은 전부 **되돌릴 수 있는 자리**(doc·plan·call)에만
> 닿습니다. 담은 학교·인원·우리 학교는 이 문으로 바뀌지 않습니다 — 사람이 고른 것입니다.

### 앱 D v0.4 → v0.6 — 규칙을 표에서 함수로

**세 학년 복식(3복식)** 을 넣으면서 부딪힌 자리입니다. 배치마다 「a 는 direct, b 는
indirect」처럼 **칸마다 역할을 적어** 두었는데, 학년이 셋이 되면 그 표가 아홉 줄이 되고
**한 줄만 빠뜨려도 조용히 어긋납니다.**

```js
function roleOf(kind, w) {
  if (kind === 'common') return 'common';
  if (kind === 'roam')   return 'indirect';
  return kind === w ? 'direct' : 'indirect';
}
```

규칙은 여전히 하나입니다 — **직접지도를 받는 학년은 언제나 하나뿐.**
검사도 표를 세는 대신 **규칙을 모든 경우에 대해** 확인합니다(두 학년일 때도, 세 학년일 때도).

그 밖에 **한 화면 4,400px 을 걸음 셋으로**, 미리보기 452px → 700px, 예시안 셋,
지도안+학습지 한 뭉치, 가로 인쇄, 점검 결과를 종이에.

### 앱 C v0.7 → v0.8 — 학생이 쓰는 앱답게

**같은 단추가 두 가지 다른 일을 하고 있었습니다.** 「새 책 만들기」가 저장소가 열리면
책을 한 권 더하고, **안 열리면 지금 책을 지웠습니다.** 사파리 사생활 보호 창처럼 넓은
저장소가 안 열리는 자리가 실제로 있고, 쓰는 사람은 자기가 어느 쪽인지 모릅니다.

그리고 **지운 것을 되살릴 길이 없었습니다.** 학생이 쓰는 앱인데요.
**확인창은 잘못 누르는 것을 못 막습니다** — 누르던 손이 그대로 「예」를 누릅니다.
묻지 말고 **되돌릴 수 있게** 했습니다(12초, 한 걸음만 기억).

## 〔2026. 8. 7.〕 검사가 검사할 대상을 베껴 적고 있었습니다

메인 페이지의 **일곱 앱 판 번호·검사 개수가 전부 낡아** 있었습니다.
앱 E 는 화면이 v0.4 인데 메인은 **v0.1** 이었습니다.

검사가 있었는데도 몰랐습니다 — **그 검사가 숫자를 손으로 베껴 적고 있었기** 때문입니다.
페이지와 검사 파일이 **함께 낡으면 아무 말도 하지 않습니다.**

```js
// 이랬습니다
const declared = { 'a-circuit': 88, 'e-together': 133, ... };
// 이렇게 바꿨습니다 — 앱이 스스로 말하는 판을 읽어서 견줍니다
const m = fs.readFileSync(appIndex, 'utf8').match(/<span>(v[\d.]+)<\/span>/);
```

**검사가 검사할 대상을 베껴 적고 있으면 검사가 아닙니다.**
마스터 7장 함정 **35번**에 적었습니다. 함정 12번(문서의 숫자가 서로 어긋난 것)과 같은 자리입니다.

## 0. 왜 대시보드에서 앱으로 전환했나

원래 계획(`06. 실행계획(1)`)은 「경북 학령인구 데이터 플랫폼」 프로토타입이었습니다. 그 계획 자체는 지금도 옳습니다. 문제는 전제였습니다.

```
06. 실행계획(1)/data/raw/        D1~D9 폴더만 있음 · 파일 0건 · 0B
06. 실행계획(1)/data/processed/  0건
```

**받아 놓을 자리는 만들어져 있지만 데이터가 한 건도 없었습니다.** 프로토타입은 5개 화면이 다 돌아가지만 표시되는 모든 수치가 코드가 생성한 더미입니다. 이 상태로 8월을 더 쓰면 "더 예쁜 더미"가 나올 뿐이었습니다.

반면 기획서(2)의 서비스들은 외부 데이터 없이 완성됩니다. 사용자가 데이터를 만들기 때문입니다.

**대시보드는 폐기가 아니라 대기입니다.** 복귀 조건은 D2(학년별 학생·학급 수) 확보입니다.

## 1. 브랜드

### 첫 안을 버렸습니다

처음 만든 마크(호 + 빈 고리 + 채워진 점 + 끊긴 바닥선)를 512px로 렌더해 보니 **지팡이 손잡이**처럼 보였습니다. 주황 점이 허공에 떠 있고 바닥선 두 개는 흘린 자국 같았습니다. 화면에서는 그럴듯했는데 실제로 뽑아 보니 아니었습니다.

후보 8개를 만들어 **큰 크기·16px·워드마크 결합·앱 아이콘·흑백**을 한 장에 놓고 비교했습니다.

**결정: 점을 없앴습니다.** 점은 크면 공처럼 보이고 작으면 사라집니다. 대신 도착 지면을 강조색으로 칠하니 "도달하는 곳"이라는 의미가 도형 자체에 들어갔습니다. 선 세 개로 줄었고 16px에서도 살아남습니다.

### 색은 계산해서 골랐습니다

후보 25개의 명도 대비를 전부 계산해 통과한 값만 남겼습니다. 여기서 하나 건졌습니다 — 처음 잡았던 밝은 주황 `#E8862B`는 흰 배경 대비가 **2.67**이라 텍스트에 쓸 수 없었습니다.

**Amber를 둘로 나눴습니다.** 텍스트 `#A8560A`(4.98), 도형 `#CE6410`(3.65).
이걸 지금 안 잡았으면 앱 3종을 다 만든 뒤 11월 접근성 자가진단에서 색을 전부 바꿔야 했습니다.

### PNG를 추가했습니다

원래 SVG만 만들었는데, **한글(HWP)은 SVG 삽입이 제대로 안 됩니다.** 공문·계획서·발표자료가 전부 한글과 PPT인 환경에서 SVG만 주면 아무도 못 씁니다. 투명 배경 PNG 20종을 뽑았습니다.

만드는 과정에서 `qlmanage`의 함정 두 개를 만났습니다 — 정사각 썸네일만 만든다는 것, 요청 크기와 같은 내재 크기를 주면 84%로 축소한다는 것. `export-png.py`에 해결책이 들어 있습니다.

## 2. 앱 A — 순회교사 통합 시간표

### 8월에 뺐던 것을 되살렸습니다

계획서 3장이 이 앱을 두고 「**주제 정합성이 가장 높다**」고 적어 놓고도 만들지
못했습니다. 학령인구 감소 → 소규모학교 증가 → 순회·겸임 교사 증가. 인과가
직선인데도 그랬습니다.

이유는 **학교 좌표가 없었기 때문**입니다. 계획서가 이 앱의 존재 이유로 꼽은 것이
「이동 시간 충돌 경고」인데, 거리를 모르면 이동 시간을 말할 수 없습니다.
그래서 자리를 앱 D(복식학급)에 내주었습니다.

8월 3일, **앱 C를 위해 경상북도 학교 917곳의 위도·경도를 구웠습니다.**
그 자료가 이 앱을 가능하게 했습니다. 제외 판정 당시와 조건이 달라졌습니다.

### 다른 시간표 도구와 갈리는 두 자리

**① 학교마다 종 치는 시각이 다릅니다.**
A중 3교시는 10:40, B초 3교시는 10:50에 시작합니다. 「3교시」라는 말로는 두 수업이
겹치는지, 사이에 몇 분이 있는지 알 수 없습니다. 그래서 이 앱은 모든 판단을
**분 단위 실제 시각**으로 합니다. 교시 번호는 사람이 부르는 이름일 뿐입니다.

**② 학교 사이에는 이동 시간이 있습니다.**
쉬는 시간 10분에 28km 떨어진 학교로 갈 수는 없습니다. 다른 시간표 도구에는
이 개념이 아예 없습니다.

### 규칙을 경고가 아니라 구조로

> 교사는 한 시점에 한 학교에만 있을 수 있다.

**이미 찬 시각의 교시는 눌리지 않습니다.** 왜 못 누르는지도 칸에 적습니다
(`길안초 겹침`). 두 학교에 동시에 있는 시간표를 만들 방법이 앱 안에 없습니다.
앱 B의 무기명, 앱 D의 복식 배치와 같은 방식입니다.

### 경고로 남긴 것 — 판단이 필요해서

**이동 시간 부족**은 막지 않습니다. 그 사이가 급식 시간일 수도 있고, 이미 학교와
조율해 둔 것일 수도 있습니다. 기계가 대신 결정할 일이 아닙니다.

대신 눈에 걸리게 합니다. 시간표에서 빈 자리를 채워 칠하고, 아래에 글로 다시 적고,
「고치러 가기」로 그 수업까지 데려다줍니다. 반대로 **여유가 넉넉한 이동은 얇게**
긋습니다. 세 시간 비는 자리를 「이동」이라고 크게 칠해 놓으면 정작 위험한 자리가
묻힙니다.

### 어림값을 정확한 척하지 않습니다

```
필요 시간 = 직선거리 × 1.35(도로 사정) ÷ 시속 50km × 60 + 10분(준비)
          단, 아무리 가까워도 15분
```

경북은 산이 많아 실제로는 더 걸리기도, 고속도로가 있으면 덜 걸리기도 합니다.
그래서 화면에 **「어림값」**이라 적고, **교사가 고칠 수 있게** 했습니다. 고친 값에는
「직접 적음」이 붙고 종이에도 그대로 나옵니다. 다녀 본 사람이 제일 잘 압니다.

좌표를 모르는 학교는 **어림하지 않습니다.** 0분으로 두면 경고가 조용히 사라집니다.

### 개인정보

학생 이름을 받는 칸이 **없습니다.** 학급은 `3-1` 까지, 교사 본인 이름도 받지
않습니다. 필요가 없습니다.

### 잡은 것

인쇄본에서 이동 표시가 표를 덮었습니다. 화면용 `.mv` 가 `position:absolute` 인데
종이에서도 같은 이름을 써서 그것이 따라온 것입니다. 이름을 `.pmv` 로 갈랐습니다.
**화면에서 멀쩡한 것이 종이에서 깨진 세 번째 사례입니다**(앞선 둘: 앱 C 표지 흰 글씨,
앱 C 지도 쪽 2단 배치).

## 3. 앱 B — 학급 자율 의사결정 보드

### 왜 이 앱인가

**소규모 학급은 인원이 적어 익명이 성립하지 않습니다.** 6명 학급에서 손을 들면 누가 무슨 의견인지 다 보입니다. 그래서 무기명 도구가 대규모 학급보다 오히려 절실합니다.

이 논리가 앱과 "학령인구 감소 대응"을 잇습니다. 학급이 작아질수록 이 도구가 더 필요해집니다.

### 무기명을 구조로 보장했습니다

기능이 아니라 구조입니다. 끄거나 우회할 수 없습니다.

| 장치 | 없으면 |
|---|---|
| 이름 칸이 아예 없음 | — |
| 제출 시각 미저장 | 시각 순서로 역추적됨 |
| 모으는 동안 **개수만** 표시 | 방금 낸 사람 글이 화면에 뜨면 익명이 아님 |
| 공개 순간 **순서 섞기** (Fisher-Yates) | 제출 순서가 곧 단서 |
| 투표 중 **집계 숨김** | 먼저 고른 사람을 따라감 |

세 번째와 다섯 번째가 핵심입니다. 보통 이런 앱은 제출하면 바로 목록에 뜨는데, **소규모 학급에서는 그게 곧 신원 노출**입니다.

### 기획서에서 바꾼 것

- **감정 체크인 제외** — 학생 개인의 심리 상태 기록. 개인정보 영향평가 없이 배포 불가
- **④와 ⑦ 통합** — 안건함·투표·약속 체크가 70% 중복
- **중복 투표 미차단** — 계정 없이는 불가능하고, 계정을 넣는 순간 무기명이 깨짐. 교사가 지켜보며 기기를 돌리는 방식이라 실제로는 문제가 안 됨

### v0.2에서 한 일 (UI 개선 + 저작권)

- **단계 표시를 로고의 도약 궤적으로** 만들었습니다. 낮은 지면에서 출발해 5개 점을 지나 높은 주황 지면(결정)에 착지합니다. 브랜드 심볼의 의미와 앱의 흐름이 같은 모양이라 억지가 없습니다.
- 모인 개수를 칩으로 시각화 (내용은 여전히 안 넣음)
- **대비 4곳이 기준 미달**이라 고쳤습니다 — 전부 다크모드에서 밝아진 브랜드 색 위에 흰 글자를 얹은 같은 실수. `--solid-*` + `--solid-fg` 짝을 도입했습니다.
- SVG 표현 속성의 `var()`를 CSS 클래스로 교체

### 잡은 버그

`db.get()`이 살아 있는 객체를 돌려주는데 `save()` 뒤에 `m.step`을 읽고 있어서 안내 문구가 항상 틀리게 나왔습니다.

## 4. 앱 C — 지역 탐방 디지털 스토리북

### 가장 큰 문제는 사진 용량이었습니다

폰 사진 1장 3~5MB, 브라우저 저장 공간 5MB. **압축 없이는 첫 페이지에서 터집니다.**

캔버스로 재압축합니다 (1600px·82%, 보통 90% 이상 감소). 그리고 이걸 **감추지 않고 보여줍니다** — `92% 줄였습니다 · 2.9 MB → 234 KB · 1600×1200`. 학생이 용량이라는 개념을 눈으로 배웁니다.

저장 실패 시 **되돌리고 알립니다.** 사진이 조용히 사라지면 학생이 작업을 잃습니다.

### v0.3에서 고친 것

**표지가 인쇄되지 않던 문제.** 원인은 브라우저가 CSS 배경을 기본으로 인쇄하지 않기 때문이었습니다. 표지 바탕이 `background: linear-gradient(...)`인데 안 찍히고 글자는 흰색이라 **흰 종이에 흰 글씨**가 나왔습니다.

→ 배경을 **인라인 SVG(전경 요소)** 로 바꿨습니다. `<svg><rect fill="url(#gradient)"/></svg>`는 그림이라 「배경 그래픽」 설정과 무관하게 항상 인쇄됩니다.

**EPUB 내보내기.** 외부 라이브러리 없이 ZIP 작성기를 직접 만들었습니다(CRC32 + 로컬 헤더 + 중앙 디렉터리, 전부 STORE). EPUB은 XHTML이라 태그 하나만 안 닫혀도 안 열리므로, `test-epub.js`가 실제 파일을 만들어 `unzip -t`로 무결성을 보고 풀어서 XML 적합성과 매니페스트 일관성까지 확인합니다.

**페이지 편집.** 한 장씩 / 모아 보기로 나누고, **사진 크기 조절**(크기·확대·좌우·위아래)을 넣었습니다. 글을 칠 때는 미리보기만 갱신합니다 — 전체 재렌더하면 커서가 튑니다.

**모으기(합본).** 설계상 가장 어려웠습니다. 6명×8쪽=12MB > 5MB. 그래서 **합본을 「저장하는 문서」가 아니라 「바로 내보내는 결과물」로** 다룹니다. 메모리에서만 만들고 인쇄·EPUB·파일로 즉시 내보냅니다. 화면에 "합본은 저장되지 않습니다"를 명시했습니다.

### v0.4에서 한 일

**마지막 장(판권지) 꾸미기.** 맺음말·만든 사람·학교·지도 교사를 넣고 모양 4종 중에 고릅니다. 책 제목·날짜·저작권은 자동으로 들어가고 지울 수 없습니다.

「사진으로」를 고를 때만 사진 칸이 나타납니다. 항상 보이면 흰 바탕을 쓰면서도 사진을 넣게 되고 저장 공간만 먹습니다.

**예전에 저장한 책에는 `back` 필드가 없습니다.** `backOf()`가 기본값으로 채워 돌려주므로 열 때 터지지 않습니다. 테스트로 고정했습니다 — 앞으로 필드를 추가할 때마다 같은 문제가 생깁니다.

### v0.5 — 이름값을 하게 만들었습니다

v0.4까지 이 앱은 **사진 넣는 책 만들기**였습니다. 이름에 「지역 탐방」이 붙어 있을 뿐,
경상북도도 없고 어디를 다녀왔는지도 남지 않았습니다. 사진첩과 구분이 안 됐습니다.

전환은 한 문장입니다 — **쪽마다 「어디인지」가 붙고, 그것이 모여 지도 한 장이 된다.**

**경상북도 22개 시군을 넣었습니다.** 군위군은 없습니다 — 2023년 7월 1일 대구광역시로
넘어갔습니다. 경북 교육 자료에 군위를 두면 그것부터 틀립니다. 검사가 이걸 고정합니다.

**지도는 직접 그렸습니다.** 지도 API를 쓸 수 없습니다(인터넷 없이 도는 것이 원칙).
실제 위경도를 화면 좌표로 옮겨 SVG로 그리므로 **시군끼리의 상대적 위치가 실제와 같습니다.**

다만 **경계선 전체는 그리지 않았습니다.** 손으로 그리면 반드시 틀리고, 경북 선생님은
그 모양을 압니다. 사실이 분명한 것 — 동해안선과 바다 — 만 그렸습니다.
그 선 하나로 「경북」으로 읽히고, 오른쪽이 바다라는 것만 알면 방향이 잡힙니다.
울릉은 경도 130.9도라 같이 그리면 육지가 납작해져서 딸린 상자로 뺐습니다.

> 〔2026. 8. 4. 고침〕 **이 판단은 뒤집혔습니다.** 손으로 그릴 필요가 없어졌기 때문입니다 —
> 통계청 SGIS 행정경계(공공누리 제1유형)를 받아 **진짜 시군 경계를 구웠습니다.**
> 자세한 것은 아래 9-2 장. 손으로 찍은 해안선은 지웠고, 그 자리에 시군 21곳 + 울릉이 들어갔습니다.

**탐방 지도 쪽이 이 앱의 얼굴입니다.** 다녀온 곳이 순서대로 점선으로 이어집니다.
표지 다음에 들어가고 인쇄물·EPUB에도 그대로 갑니다. EPUB에서는 SVG를 XHTML에
그대로 넣어 용량이 거의 안 들고 확대해도 안 깨집니다. 대신 태그 하나만 안 닫혀도
책이 안 열리므로, `test-epub.js` 가 지도 쪽이 든 책을 실제로 만들어 XML 적합성까지 봅니다.

**초성 검색**을 넣었습니다 — `ㅂㄱㅅ` → 불국사. 아이들이 쓰는 법에 맞췄습니다.

**기본 탐방지는 출발점일 뿐입니다.** 학교가 실제로 가는 곳은 유명한 명소가 아닌 경우가
많습니다. 「탐방지 더하기」로 마을 앞 개울, 오래된 나무를 넣게 했습니다.
> 배포 전에 경북 선생님이 기본 목록을 한 번 훑어 주는 것이 안전합니다.

### v0.6 — 저장 공간 · 우리 학교 · 표지 (2026. 8. 3.)

#### 4.2MB 벽을 없앴습니다

이 앱의 가장 오래된 제약이었습니다. localStorage 가 5MB 언저리에서 막히니
**한 번에 한 권**밖에 둘 수 없었고, 합본은 아예 저장하지 못했습니다.
사진이 들어가는 앱에서 이것은 기능 제한이 아니라 **쓰지 못하게 하는 벽**입니다.

같은 「이 기기 안」을 지키면서 넓힐 길이 있었습니다. **IndexedDB** 입니다.
`file://` 로 열어도 크롬에서 동작하는지 먼저 확인했습니다 — 8MB 를 넣었다 빼 봤고,
`navigator.storage.estimate()` 가 알려 준 몫은 **555 GB** 였습니다.

| | 예전 | 지금 |
|---|---|---|
| 담기는 양 | 4.2MB | 브라우저가 내주는 몫 (보통 수십 GB) |
| 둘 수 있는 책 | 한 권 | 몇 권이든 — 「책장」 탭 |
| 합본 저장 | 안 됨 | 됨 |
| 인터넷 | 안 씀 | **여전히 안 씀** |

넓어진 것은 저장소지 원칙이 아닙니다. 나가는 요청은 여전히 하나도 없습니다.

**못 쓰는 브라우저에서는 예전 방식으로 물러납니다.** 그리고 왜 한 권인지,
어느 브라우저로 열면 되는지를 화면에 적습니다. 조용히 못 하고 넘어가면
사파리에서 연 선생님은 이유를 알 수 없습니다.
v0.5 까지 만들던 책은 처음 열 때 책장으로 **옮겨 옵니다.**

#### 우리 학교를 이름으로 찾습니다 — 공공데이터

예전에는 「우리 학교가 있는 곳」이 시군 고르기였습니다. 안동시를 고르면
임하면 학교나 풍천면 학교나 같은 점이었습니다.

**경상북도의 학교 917곳**(초 474 · 중 260 · 고 183)을 **위도·경도까지** 담았습니다.
**분교장 18곳도 그대로** 들어 있습니다 — 작은 학교를 위한 앱이 분교장을
빠뜨리면 앞뒤가 맞지 않습니다.

공공데이터를 **두 곳**에서 받았습니다. 하나로는 안 됐습니다.

| | 교육정보 개방 포털 | 학교알리미 |
|---|---|---|
| 이름·학교급·주소 | ○ | ○ |
| **위도·경도** | **없음** | **`LTTUD`·`LGTUD`** |

인증키가 **32자리 16진수로 생김새가 똑같아** 처음 받은 키가 어느 쪽 것인지
바로 알 수 없었습니다. 양쪽에 한 번씩 물어 가려냈습니다 — 개방 포털에서는
정상 응답, 학교알리미에서는 0으로 채운 가짜 키와 똑같은 거절이었습니다.
이 확인 방법을 `open api/README.md` 에 적어 두었습니다. 다음에 또 겪습니다.

받아서 **파일 안에 구웠습니다.** 앱이 열릴 때 부르는 것이 아닙니다.
그래서 「어떤 자료도 외부로 전송하지 않습니다」가 그대로 참입니다.
실제로 학교알리미 서버는 CORS 머리를 주지 않아 브라우저에서 부를 수도 없습니다.
구워 넣는 것이 원칙에도 맞고 유일하게 되는 방법이기도 했습니다.

#### 「시군」과 「학교」는 다릅니다

안동시 길안초등학교에서 청송군까지:

| 기준 | 거리 |
|---|---|
| 안동시 한가운데 (예전) | 30km |
| **길안초등학교 자리 (지금)** | **15km** |

길안면은 안동 시내가 아니라 청송 쪽에 붙어 있습니다. 절반입니다.
현장학습 계획을 세울 때 답이 그대로 달라지는 자리라, 이 차이를 검사로 고정했습니다 —
*「시군 한가운데를 쓸 때와 거리가 다르다」*.

#### 손으로 고친 세 곳

굽고 나니 917곳 중 3곳에 좌표가 없었습니다. 하나씩 까 보니 이유가 다 달랐습니다.

| 학교 | 무엇이었나 | 어떻게 |
|---|---|---|
| (가칭)호명중학교 | 2027년 3월 **개교 예정.** 주소로 적힌 곳이 예천교육지원청 | 목록에서 **뺐습니다** |
| 지품천초등학교 | 2026년 3월 개교(지례초 개명)라 좌표가 아직 없음 | **같은 도로명주소**의 지례초등학교 좌표를 넣었습니다 |

세 번째를 억지로 채우지 않은 것이 중요합니다. 좌표가 없는 학교는 시군 자리에
찍고 **화면이 그렇게 말합니다.** 어림한 것을 정확한 척하지 않습니다.
다시 구워도 이 셋은 남습니다 — 스크립트가 이미 있는 좌표를 지우지 않게 고쳤습니다.

> OSM(Overpass)으로도 좌표를 받아 봤습니다. 918곳 중 **670곳만** 이름이 맞았고
> 맞은 것이 정말 맞는지 확인할 방법이 없었습니다. 아이들에게 보여 줄 지도에
> 출처를 못 대는 좌표를 섞을 수는 없어 쓰지 않았습니다. 결국 공식 자료를
> 기다린 것이 맞았습니다.

#### 표지를 셋으로 나눴습니다

「색으로 · 사진으로 · 단정하게」 셋뿐이라 한 반 스무 권이 모두 같은 표지였습니다.
**바탕 10 × 무늬 6 × 글자 자리 3** 으로 나눴습니다. 180가지가 되지만
아이가 고르는 일은 여전히 셋입니다.

- 한지 · 흰 종이처럼 밝은 바탕에서는 **글자와 상표가 저절로 어두워집니다.**
- 무늬는 CSS 배경이 아니라 **SVG** 입니다. 「배경 그래픽 인쇄」를 꺼도 나옵니다.
  (v0.3 에서 표지가 하얗게 인쇄되던 것과 같은 이유입니다.)
- **마지막 장이 표지 바탕을 따라갑니다.** 앞뒤가 따로 노는 책은 만들다 만 것 같습니다.
- 예전 책은 그대로 보입니다 — `grad`→새벽, `solid`→단정하게.

### 기획서에서 뺀 것

GPS 미션맵(권한·지도API·서버), 지역 역사 DB(**콘텐츠는 학생이 채우는 것**), 음성 녹음(용량 + 목소리는 사진보다 민감), 온라인 출판(서버).

v0.5의 지도는 GPS 미션맵과 다릅니다. **위치 권한도 지도 API도 서버도 쓰지 않습니다.**
교사가 「어디를 다녀왔다」고 고르는 것이고, 지도는 앱 안에 글자로 들어 있습니다.

## 5. 앱 D — 복식학급 수업 도우미

### 왜 새로 세웠나

기획서(2) 10종이 소진됐습니다. 남은 건 ② 하나인데 그마저 「학급 단위만」 원칙과 충돌합니다.

**학령인구 감소 → 소규모학교 증가 → 복식학급 증가.** 인과가 직선이고, 앱 A(순회교사)를 뺀 이유였던 "사용자 없음"을 이 앱이 메웁니다. 복식학급 담임은 경북 소규모학교에 흔합니다.

### 규칙을 경고가 아니라 구조로

> 교사는 한 시점에 한 학년만 직접지도할 수 있다.

블록마다 자유롭게 배정하면 "3학년 직접 + 4학년 직접"이라는 불가능한 상태를 만들 수 있습니다. 대신 **성립 가능한 배치 네 가지**(ㄱ직접 / ㄴ직접 / 공통 / 둘 다 스스로) 중에서만 고르게 했습니다. 잘못된 상태를 표현할 방법 자체가 없습니다.

### 경고로 남긴 것 — 판단이 필요해서

| 살펴볼 점 | 기준 |
|---|---|
| 직접지도 시간 치우침 | 차이 10분 초과 |
| 너무 오래 혼자 | 연달아 15분 초과 |
| 둘 다 스스로가 김 | 10분 초과 |
| **스스로 할 거리 없음** | 간접 구간이 있는데 준비물이 빔 |

마지막이 제일 중요합니다. 복식수업이 실패하는 건 직접지도 받는 학년 때문이 아니라 **혼자 해야 하는 학년의 할 거리가 없을 때**입니다.

### 시간 배치표의 맨 아랫줄

```
         0–5    5–10   10–15  15–20  20–25  25–30  30–35  35–40
3학년    함께   직접   스스로 직접   스스로 직접   스스로 함께
4학년    함께   스스로 직접   스스로 직접   스스로 직접   함께
선생님   함께   3학년  4학년  3학년  4학년  3학년  4학년  함께
```

**「선생님」 줄이 이 도구의 요점입니다** — 그 시간에 어디 계신지 한눈에 보입니다.

### v0.2에서 넓힌 것

학년을 적는 대신 **토글로 고르게** 했습니다. 한쪽에서 고른 학년은 반대쪽에서 눌리지 않습니다 —
배치 네 가지와 같은 방식으로, 같은 학년 둘이라는 잘못된 상태를 만들 방법 자체를 없앴습니다.

**학습지 만들기**를 넣었습니다. 복식수업에서 학습지는 곁들이가 아니라 뼈대입니다.
그래서 만드는 화면에 **그 학년이 연달아 혼자 있는 시간**을 함께 띄우고, 점검이 이 탭을 봅니다 —
한 학년을 10분 넘게 혼자 두면서 그 학년 학습지가 비어 있으면 따로 짚습니다.

**미리보기**를 넣었습니다. 그전까지는 지도안을 보려면 인쇄 대화상자를 띄우는 수밖에 없었습니다.
미리보기와 인쇄물이 **같은 함수·같은 CSS(`.sheet`)** 를 쓰게 했습니다. 따로 만들면 반드시 어긋납니다.

### v0.3에서 고친 것 — 대부분 실제로 써 보고 나온 것

| 무엇이 문제였나 | 어떻게 고쳤나 |
|---|---|
| **구간을 눌러야** 활동 칸이 나타남 | 여덟 구간을 **전부 펼침**. 위에서 아래로 죽 적으면 끝 |
| 미리보기가 아래에 있어 짜면서 못 봄 | **왼쪽=쓰는 곳 / 오른쪽=보는 곳**. 미리보기가 화면에 붙어 따라옴 |
| 보관함에 쌓이면 어느 차시인지 못 찾음 | 저장할 때 **차시 이름**을 붙임 |
| 준비물이 두 번 들어감 | 한글 조합 중 엔터를 거르고, 다시 그리기 전에 칸을 비움 |

**AI 초안 도우미에서 API 키를 걷어냈습니다.** v0.2는 교사 개인 Gemini 키로 브라우저에서 곧바로 불렀습니다.
학교에서 키 발급이 막히는 일이 잦고 공용 컴퓨터에 키를 남기는 것도 께름칙해서,
**프롬프트를 만들어 주고 JSON을 받는** 방식으로 바꿨습니다. 이제 앱에 네트워크 코드가 한 줄도 없습니다.

바꾸면서 규칙 하나를 더 세웠습니다 — **AI가 보낸 배치라도 네 가지를 벗어나면 받지 않습니다.**
사람이 못 만드는 상태를 AI라고 만들 수 있으면 이 앱의 핵심 설계가 무너집니다.

좁은 화면에서 **페이지가 옆으로 밀리던 문제**도 잡았습니다. v0.1부터 있던 것입니다.
배치표를 감싼 `.tlwrap` 이 `overflow-x:auto` 인데도 표가 빠져나갔는데,
원인은 표 안의 스크린리더용 `<caption>` 이 `position:absolute` 라 잘리지 않은 것이었습니다.
`position:relative` 를 줘서 감싸개가 포함 블록이 되게 했습니다.

| 2 | **옥전초등학교** | **의성군** | 10.4km | 27분 |
| 3 | **파천초등학교** | **청송군** | 12.2km | 30분 |

**두 번째로 가까운 학교가 다른 군에 있습니다.** 같은 안동인 길주초등학교(16.5km)보다
의성 옥전초가 6km 더 가깝습니다.

앱 C를 만들 때 나왔던 관찰(*「안동시 한가운데에서 청송까지 30km, 길안초 자리에서는 15km」*)이
여기서는 **기능 자체**가 되었습니다. 검사가 이것을 고정합니다.

그리고 이 사실에는 실무가 딸려 옵니다 — **시군이 다르면 교육지원청도 다릅니다.**
공문 경로가 둘이 됩니다. 목록에도, 종이의 「전화로 물어볼 것」에도 그렇게 적힙니다.

### 「함께가 항상 이득」이라고 말하지 않습니다

버스 계산에서 **전체 대수는 절대 늘지 않습니다** (`ceil(a/s)+ceil(b/s) ≥ ceil((a+b)/s)`).
검사가 무작위 200번으로 확인합니다.

그런데 **1인당 부담은 늘 수 있습니다.**

| | 혼자 | 함께 |
|---|---|---|
| 우리 40명 | 1대 · 1인당 12,500원 | 2대를 50명이 나눔 · **20,000원 ↑** |
| 이웃 10명 | 1대 · 1인당 50,000원 | **20,000원 ↓** |
| 전체 | 2대 100만 원 | 2대 100만 원 (**아끼는 돈 0**) |

이득만 보여 주면 큰 학교가 한 번 손해 보고 **다시는 안 합니다.**
그래서 앱이 이 경우를 그대로 적습니다. 검사가 그 문장이 화면에 나오는 것을 고정합니다.

**앱 B의 무기명, 앱 A·D의 「넣을 수 없게」와 같은 방식입니다** — 규칙을 문구가 아니라 코드로 둡니다.

### 앱이 모르는 것은 모른다고 적습니다

학교 목록에는 **학생 수가 없습니다.** 그래서 상대 학교 인원을 추측해 채우지 않고
「전화로 물어 적으세요」라고 적습니다. 비워 두면 0명으로 계산하고, 종이에는 「확인 필요」로 나갑니다.

좌표가 없는 한 곳(포항해오름중학교)은 **거리 순위에 섞지 않습니다.**
0km 로 두면 목록 맨 위에 올라와 「가장 가까운 학교」로 보이기 때문입니다.

### 지도를 하나 더 그렸습니다

앱 C의 경북 지도와 다릅니다. **우리 학교를 가운데 둔 반경 지도**입니다.
동심원이 직선거리이고, 학교급은 **모양**으로 나눕니다(초 ● 중 ▲ 고 ■) — 색만으로 알리지 않기 위해서입니다.
SVG 라 종이에도 그대로 들어갑니다.

### 같은 날 잡은 것 — 문서 여섯 곳의 숫자가 틀려 있었습니다

앱 E의 검사가 학교급별로 세면서 드러났습니다.

```
문서에 적혀 있던 것   초 473 · 중 260 · 고 184 = 917
실제로 구워진 자료     초 474 · 중 260 · 고 183 = 917
```

**합계가 맞았기 때문에 그때까지 아무도 몰랐습니다.** 여섯 곳을 모두 고쳤고,
이제 자료를 다시 구우면 이 검사에서 걸립니다.

*합계만 맞으면 넘어가게 되는 자리가 있습니다. 쪼개서 세어 봐야 보입니다.*

## 7. 앱 카탈로그

계획서 4장이 지정한 자리(`apps/index.html`)에 만들었습니다. **과제④ 웹앱스토어의 씨앗**입니다.

### 무엇을 담았나

앱을 늘어놓는 것만으로는 부족합니다. 교사가 **자기 것인지** 3초 안에 판단할 수 있어야 합니다.
그래서 카드마다 「이런 분께」를 넣었습니다 — *복식학급 담임. 지금도 종이에 손으로 짜고 계신 분*.

- 왜 이 앱들인가 — 학령인구 감소 → 소규모학교 증가 → 작은 학급·복식학급
- 앱 5종 카드 (한 줄 설명 · 이런 분께 · 특징 셋 · 화면 이름 · 열기/설명서)
- 다섯 앱이 함께 지키는 것 여섯 가지
- **학교에 나눠 주기** — 폴더째 복사, 앱 하나만 주기, 자료는 옮겨지지 않음
- 종이 안내문 인쇄 (A4 한 장)

**화면 전환(다크 모드)을 앱과 같은 키(`leap-theme`)로 씁니다.** 카탈로그에서 바꾸면 앱에서도 유지됩니다.
제품군으로 보이려면 이런 데서 어긋나지 않아야 합니다.

### 종이 안내문은 화면을 그대로 뽑지 않습니다

화면을 그대로 인쇄하면 카드가 잘리고, 무엇보다 **종이에서 링크는 쓸모가 없습니다.**
종이에는 「무엇을 하는 앱인지」와 「어떻게 여는지」만 넣었습니다. 검사가 이걸 고정합니다 —
"종이에는 링크를 넣지 않는다".

### 검사가 지키는 것

카탈로그가 깨지는 방식은 정해져 있습니다. **링크가 죽거나, 앱은 올라갔는데 판 번호가 옛것으로 남거나.**

- 링크 10개가 가리키는 파일이 **실제로 있는지** (`fs.existsSync`)
- 카탈로그에 적은 판 번호가 **앱 화면의 판 번호와 같은지**
- 카탈로그가 광고하는 내용이 사실인지 — 다섯 앱이 정말 서버를 부르지 않고, 파일 하나로 끝나고,
  인쇄 서식이 있고, 저작권이 있는지

마지막이 중요합니다. "어떤 자료도 외부로 전송하지 않습니다"라고 적어 놓고 앱에 `fetch` 가 생기면
**카탈로그가 거짓말을 하게 됩니다.** 그걸 검사가 막습니다.

## 8. 검증 방식에 대하여

문법 검사만으로는 부족해서, **최소 DOM 스텁 위에 앱을 실제로 올려 렌더 경로를 돌립니다.**

중요한 건 테스트가 지키는 대상입니다. 기능이 아니라 **원칙**입니다.

- "수집 중에는 안건 내용이 HTML에 없어야 한다" (B)
- "투표 중에는 득표수가 HTML에 없어야 한다" (B)
- "두 학년 동시 직접지도인 배치가 목록에 없어야 한다" (D)
- "사진 없는 쪽은 사진 배치를 갖고 있어도 글만 시트로 그려야 한다" (C)
- "옛 저장본에 새 필드가 없어도 터지지 않아야 한다" (C)
- "좌표를 모르는 학교가 거리 목록에 있어서는 안 된다" (E)
- "1인당 부담이 느는 학교가 있으면 화면이 그렇게 말해야 한다" (E)

나중에 누가 무심코 고쳐도 여기서 걸립니다.

### 테스트가 틀린 적이 두 번 있습니다

1. **92.5% 반올림** — 4.0MB→300KB는 92.5%라 반올림하면 93%. 앱이 맞았습니다.
2. **교차형에서 혼자 있는 시간** — 10분일 거라 봤는데 실제 5분. 혼자 있는 구간이 서로 떨어지기 때문입니다. 오히려 더 좋은 값이고, 교차형을 권하는 근거가 됐습니다.

**실패를 보면 먼저 손으로 계산해 보세요.**

### 네 번째 — 직선거리와 도로 거리 (2026. 8. 3.)

앱 C에 「우리 학교에서 얼마나 먼가」를 넣으면서, 안동–경주가 **100~130km** 일 거라고
검사를 썼습니다. 앱은 **91km** 를 내놨습니다.

손으로 계산해 보니 남북 79km · 동서 44km → 직선 90.6km. **앱이 맞았습니다.**
제가 도로 거리(약 120km)와 헷갈린 것입니다.

여기서 검사만 고치고 끝내면 안 됩니다. **교사도 똑같이 헷갈립니다.**
「약 91km」만 보고 견학 계획을 세우면 실제로는 훨씬 오래 걸립니다.
그래서 화면 표기를 **「직선 91km」** 로 바꾸고, 지도 쪽 아래에도 "거리는 직선거리"를 적었습니다.

**검사가 틀렸다고 판명나도, 왜 틀렸는지는 사용자에게도 일어날 수 있습니다.**

### 세 번째 — 시간대 (2026. 8. 3.)

카탈로그를 만들기 전에 세 앱을 다 돌려 보니 **앱 B가 1개 실패**하고 있었습니다.
「오늘 신호등이 눌린 상태」였습니다.

앱은 `LEAP.todayISO()` 로 **그 지역의 오늘**을 씁니다. 그런데 검사는 `toISOString()` 으로
키를 만들고 있었습니다. 이건 **UTC 날짜**입니다. 한국 시간 자정~오전 9시 사이에는 하루 어긋납니다.

```
지금(로컬)        2026-08-03 04:21 KST
앱이 쓰는 키      2026-08-03   ← 선생님에게 오늘은 여기 날짜
검사가 쓰는 키    2026-08-02   ← UTC
```

**이 검사는 매일 아침 9시간 동안 실패하고 나머지 15시간은 통과했습니다.**
언제 돌리느냐에 따라 결과가 달라지는 검사는 검사가 아닙니다.
또 앱이 맞고 검사가 틀렸습니다. 고친 뒤 시간대 4곳(서울·UTC·뉴욕·오클랜드)에서 확인했습니다.

**교훈**: 날짜를 다루는 검사는 앱과 **같은 방법으로** 날짜를 구해야 합니다.

### 같은 날 잡은 것 하나 더 — 판 번호가 어긋나 있었습니다

앱 C는 README와 이 문서가 v0.4인데 **앱 화면 아래에는 v0.3** 이 찍혀 있었습니다.
기능을 올릴 때 화면의 판 번호를 안 고친 것입니다.

카탈로그가 판 번호를 광고하니 이제 이게 눈에 보이는 문제가 됩니다.
그래서 **카탈로그 검사가 앱 화면의 판 번호를 직접 읽어 대조**하게 했습니다. 다시는 어긋나지 않습니다.

## 9-1. 메인 페이지 v0.3 (2026. 8. 4.)

**바깥으로 나가는 얼굴을 정리했습니다.** 자세한 값은 마스터 11장에 있고, 여기에는 **왜**만 적습니다.

**이름을 바꿨습니다.** 「학령인구 감소 대응」은 공문 제목이지 앱 이름이 아니었습니다.
브랜드가 감소를 그리지 않기로 한 것과 같은 이유로, 이름도 **하는 일**을 말하게 했습니다 —
**「작아지는 학교, 넓어지는 교육」.** 주제는 눈썹줄로 내렸습니다.

**안쪽을 걷어냈습니다.** 「무엇으로 만들었나」·「여섯이 함께 지키는 것」·「문서와 브랜드」 절을 뺐습니다.
설계 원칙과 점검 방식은 우리가 일하는 방법이지, 페이지를 받는 사람이 알아야 할 것이 아닙니다.
**지운 것이 아니라 걷어 둔 것**입니다 — 나중에 공개하기로 하면 마스터 11장을 보고 되살리면 됩니다.
무심코 되살아나지 않도록 「내부 문서로 가는 길이 없다」 점검 4개를 걸어 두었습니다.

**돌아오는 길을 만들었습니다.** 앱을 열면 되돌아올 방법이 없었습니다.
브라우저 뒤로 가기는 방법이 아닙니다 — 링크를 새 창으로 열거나 바탕화면 바로가기로 연 사람에게는
뒤로 갈 곳이 없습니다. 일곱 곳(앱 5 + 카탈로그 + 대시보드)에 홈 단추를 넣었고,
**메인의 점검이 일곱 파일을 직접 열어** 단추가 있는지, 그 경로가 정말 메인에 닿는지 확인합니다.

대시보드만 자리가 다릅니다. 사이드바 맨 아래에 두었더니 본문만큼 길어져서 한참 내려야 보였고,
메뉴 안의 「홈」(대시보드 자체의 홈 화면)과 나란히 두면 어느 쪽이 밖으로 나가는 문인지 알 수 없었습니다.
그래서 **브랜드 바로 아래, 왼쪽 화살표를 달아** 별도 칸에 놓았습니다.

**브랜드 절에서 글자가 선 위에 올라앉아 있었습니다.** 「간극」을 두 지면을 잇는 빗금 한가운데에
얹었더니 글자도 선도 읽히지 않았습니다. 어긋난 만큼을 ㄱ 자로 재고 글자를 지면 아래로 내렸습니다.
좌표가 점검에 박혀 있어 다시 올라오면 걸립니다.

**마지막을 비워 두었습니다.** 다른 연구원의 앱이 들어올 자리 3칸입니다.
빈 칸으로 보이지 않게 점선으로 두르고, 눌리지 않도록 `<a>` 가 아니라 `<div>` 로 두었습니다.
채우는 법은 그 자리 주석에 적어 두었습니다. 선생님이 앱을 찾아 여러 곳을 헤매지 않으려면
**입구는 하나여야 합니다.**

점검은 47개에서 **79개**로 늘었습니다 (다 합쳐 815 → **849**).

## 9-2. 점 지도 → 시군 경계 지도 (2026. 8. 4.)

### 지도 API 는 여전히 안 씁니다. 그런데 이유가 하나 더 늘었습니다

「인터넷을 안 쓴다」는 이유는 처음부터 있었습니다. 알아보다가 **더 결정적인 것**을 찾았습니다 —
**카카오맵·네이버지도 API 는 행정구역 경계 폴리곤을 주지 않습니다.**
지도 API 가 주는 것은 배경 타일과 마커·검색·경로입니다.
시군을 색칠하거나 경계를 그리려면 **API 를 쓰든 안 쓰든 경계 파일을 따로 구해야 합니다.**

그러면 남는 것은 「배경 타일이 필요한가」뿐인데, 우리 지도에는 도로도 건물도 필요 없습니다.
API 를 붙이면 인터넷·인증키·도메인 등록을 떠안고 얻는 것이 **안 쓰는 배경 그림**입니다.

### 받은 것

통계청 SGIS 행정경계 **시군구 GeoJSON**(공공누리 제1유형, 2018).
학교 목록과 **같은 라이선스**라 출처표시 방식이 그대로 갑니다.

경북 24개 항목이 들어 있어 둘을 손봤습니다.

- **포항시가 남구·북구로 쪼개져 있습니다.** 학교 목록은 「포항」 하나이므로 한 이름으로 모읍니다.
  구 경계선은 지우지 않았습니다 — 지우려면 위상 연산이 필요하고, 실제 지도에도 그 선이 있습니다.
- **군위군이 아직 경북으로 들어 있습니다.** 2023. 7. 1. 대구광역시로 넘어갔으므로 뺐습니다.
  빼고 나면 지도 한가운데가 뚫립니다 — **그게 맞습니다.** 그 자리는 이제 대구입니다.
  앱 C 가 이미 「군위가 없다」를 검사로 고정해 두었던 것과 같은 판단입니다.

남은 21곳 + 울릉 = **지금 쓰는 22개 시군과 정확히 일치**합니다.

### 굽는 법 — mapshaper 도 안 씁니다

`open api/bake-boundary.mjs`. 노드 기본만으로 세 가지를 합니다 — **고르고, 점을 줄이고, 담기.**
점 줄이기는 Douglas-Peucker 40줄입니다. 외부 도구를 하나 더 들이는 것보다 이쪽이 싸게 먹힙니다.

**화면 좌표로 미리 옮기지 않습니다.** 네 곳의 지도가 크기도 범위도 다릅니다 —
대시보드는 620×470 전도, 앱 E 는 우리 학교를 가운데 둔 반경 지도, 시군 상세는 한 시군만 확대.
미리 옮기면 그중 하나에만 맞습니다. 그래서 위경도로 담고, 각 앱이 제 투영으로 폅니다.

대신 **차이값으로 접었습니다.** 첫 점만 절대값(1/10000도)이고 그다음은 앞 점과의 차이입니다.
경계선의 이웃한 두 점은 아주 가까워서 차이는 대개 한두 자리입니다.
4030개 점이 **앱마다 29KB** 로 들어갑니다 (접기 전 약 64KB).

### 네 곳에 어떻게 넣었나 — 경계가 나르는 정보가 곳마다 다릅니다

| 곳 | 경계의 역할 | 그래서 |
|---|---|---|
| 메인 작은 지도 | 「경북이구나」 | 면을 옅은 주색으로 칠하고 시군 이름 병기 |
| 대시보드 시군 분포 | **바탕.** 값은 여전히 원이 나름 | 원보다 연하게, `pointer-events:none` |
| 앱 C 탐방 지도 | **뭍.** 바다를 깔고 그 위에 얹음 | 손으로 찍은 해안선을 대체 |
| 앱 E 이웃 찾기 | 이웃이 **어느 시군**인지 | 거리 고리보다 더 연하게. 화면 밖으로 잘리는 게 맞음 |

**시군 면에 값을 칠하지 않았습니다(코로플레스 아님).** 시군 넓이는 학교 수와 아무 상관이 없어서,
넓은 봉화가 진해 보이면 없는 뜻이 생깁니다. 값은 원 넓이가 나릅니다.

### 앱 C 의 창을 넓혀야 했습니다

점만 찍을 때는 `LON0 = 128.05` 로도 됐습니다. 시군 중심이 다 들어왔으니까요.
경계를 넣으니 **서쪽(127.80)과 북쪽(37.15)이 잘렸습니다.** 창을 127.76~129.62 / 35.53~37.19 로 넓히고,
가로세로 배율을 cos(36.4°)≈0.805 에 맞춰 `MAP_W` 를 400 → 410 으로 고쳤습니다.
안 맞추면 경북이 옆으로 늘어납니다.

곁들여 검사 둘이 깨졌습니다 — 「polyline 이 2개(해안선 + 다닌 길)」를 세고 있었는데,
해안선이 path 가 되면서 **1개**가 되었습니다. 세는 대상을 고치고, 대신
「시군 경계로 뭍이 그려진다」를 화면용·종이용 둘 다에 넣었습니다.

### 낡지 않게 하는 장치

좌표를 굽는 것과 같은 문제입니다 — **한 곳만 다시 구우면 나머지가 조용히 낡습니다.**
메인 점검이 네 파일의 `GB_POLY` 블록을 꺼내 **글자 하나까지 같은지** 봅니다.
군위가 되살아나도, 시군이 22곳이 아니어도 거기서 걸립니다.

### 남은 것

기준연도가 **2018** 입니다. 시군 경계 자체는 그 뒤로 바뀐 것이 없지만(군위는 소속만 바뀜),
공문에 쓸 것이면 최신본으로 다시 굽는 편이 안전합니다.
`business.juso.go.kr` 신청이 처리되면 같은 스크립트에 그 파일을 넣기만 하면 됩니다 —
속성 칸 이름(`SIG_CD` 등)과 시도 코드 `47` 을 이미 함께 받도록 해 두었습니다.
