# 데이터 백엔드 기반

이 폴더는 지금 화면을 갑자기 DB 방식으로 바꾸기 위한 것이 아니라, 담당자가 바뀌어도 같은 데이터를 다시 만들고 검증할 수 있게 하는 출발점이다. 현재 공개 화면은 마지막으로 검증된 정적 스냅샷을 계속 사용한다.

## 이미 채워 둔 것

- `functions/shared/data-catalog.js`: D1~D10 자료의 기관, 기준시점, 갱신주기, 수집 프로그램, 현재 상태
- `migrations/0001_initial.sql`: Cloudflare D1용 출처·수집이력·학교·연도통계·인구전망·품질오류·버전 테이블
- `wrangler.backend.example.jsonc`: 향후 D1과 R2를 연결할 때 쓸 바인딩 이름
- `/api/data-status`: 배포된 데이터 목록과 런타임 키 인식 여부를 값 노출 없이 확인하는 읽기 전용 API
- `scripts/check.mjs`: 목록의 누락·중복·잘못된 파일 경로와 D1 스키마를 한 번에 검사

## 지금 실행할 명령

프로젝트 루트에서 다음 한 줄만 실행하면 된다.

```bash
node backend/scripts/check.mjs
```

이 검사는 사이트 굽기에도 자동으로 포함된다. 인증키 값은 이 폴더에 넣지 않는다.

## 나중에 D1/R2를 실제로 만들 때

아래 작업은 Cloudflare 계정의 저장공간과 운영 책임자를 정한 뒤 한 번만 수행한다.

1. D1 데이터베이스 `team-leap-data`를 만든다.
2. R2 버킷 `team-leap-data-raw`를 만든다.
3. `wrangler.backend.example.jsonc`를 복사하고 D1 ID를 채운다.
4. `migrations/0001_initial.sql`을 D1에 적용한다.
5. 수집 프로그램이 원본 응답을 R2에 보존한 뒤, 검증을 통과한 자료만 D1에 넣도록 연결한다.
6. 공개 대시보드는 새 버전이 성공했을 때만 바꾸고, 실패하면 직전 성공 스냅샷을 유지한다.

## 운영 원칙

- 학교명 대신 공식 학교코드, 시군명 대신 행정표준코드를 연결키로 쓴다.
- 원본 응답과 SHA-256 해시를 남겨 나중에 같은 결과를 재현한다.
- 학생·교직원 개인자료는 수집하지 않는다.
- 환경변수 이름만 Git에 저장하고 실제 키는 Cloudflare Runtime Secret 또는 GitHub Actions Secret에 둔다.
- 새 자료는 합계·중복·누락·좌표·전년 대비 급변 검사를 통과한 뒤 공개한다.
